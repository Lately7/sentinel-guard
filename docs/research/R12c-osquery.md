# R12c — osquery 5.24.0 Windows source review

**Scope distinction.** Sentinel’s locked smart scan covers watched folders, user and All Users Startup, HKCU/HKLM Run and RunOnce in both registry views, readable Task Scheduler executable actions, and running process image files. It excludes elevation, process memory and UNC paths (`sentinel-guard/docs/handoff/PROJECT_CONTEXT.md:191-206`). The other osquery tables below inform evidence and coverage reporting; they do not enlarge that scope.

**Privilege terms in the tables:** “current token” means a normal user can try the call, but the object’s ACL can deny it. A denied or malformed entry must be recorded as unavailable or partial coverage, never as an absent threat.

### Authenticode result mapping and a catalog caveat

| `WinVerifyTrust` result | osquery output |
|---|---|
| `ERROR_SUCCESS` | `trusted` |
| `CRYPT_E_SECURITY_SETTINGS` | `valid` |
| `TRUST_E_EXPLICIT_DISTRUST` | `distrusted` |
| `TRUST_E_NOSIGNATURE` | `missing` only if its subsequent `GetLastError()` is one of `TRUST_E_NOSIGNATURE`, `TRUST_E_SUBJECT_FORM_UNKNOWN`, `TRUST_E_PROVIDER_UNKNOWN`; otherwise the row is dropped |
| `TRUST_E_SUBJECT_NOT_TRUSTED` and **every other result**, including a specific revocation or chain error | `untrusted` |
| `invalid` | The enum and output string exist, but `verifySignature` never assigns this value |

These mappings and the `GetLastError()` branch are at `osquery/tables/system/windows/authenticode.cpp:67-134,180-261`. On any non-`missing` result, the subsequent certificate extraction is mandatory; missing `SPC_SP_OPUS_INFO` publisher information or an absent certificate drops the row (`authenticode.cpp:264-304,363-478,481-537`). Thus an empty table result is **not** equivalent to “unsigned.”

**Catalog inference from code:** osquery confirms that a catalog was found for the file’s calculated hash, then calls `WinVerifyTrust` with `WTD_CHOICE_FILE` on the catalog path (`authenticode.cpp:137-177,197-207,446-475`). It does not supply `WINTRUST_CATALOG_INFO` containing the original member path, tag and hash. That verifies the catalog as a file, rather than explicitly verifying the original file **as that catalog member** in the trust call. Microsoft defines `WTD_CHOICE_CATALOG` and those member fields for that operation. [Microsoft: WINTRUST_DATA](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-wintrust_data), [WINTRUST_CATALOG_INFO](https://learn.microsoft.com/en-us/windows/win32/api/Wintrust/ns-wintrust-wintrust_catalog_info). Gate v2 should not copy this shortcut.

## Implications for Gate v2 and smart scan

| Locked source or evidence | Python call and handling | If access fails |
|---|---|---|
| Watched folders and Startup directories | Use `os.scandir` for bounded enumeration. | HKCU/HKLM `Run` and `RunOnce`, both views | Python stdlib `winreg.OpenKey`/`EnumValue` with `KEY_READ \| KEY_WOW64_64KEY`, then `KEY_READ \| KEY_WOW64_32KEY`, for each of four named keys. | Running process images | Through `ctypes`, take a process snapshot with `CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS)` and `Process32FirstW/NextW`; for each PID call `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` and `QueryFullProcessImageNameW`, growing the WCHAR buffer as needed. **Decision rule inferred for Gate v2:** maintain coverage at the source-entry level as well as the file level. A successful scan of every *discovered* file cannot certify a smart scan when a registry view, task folder, Startup directory, process image, or identity check was inaccessible. That inference follows from the locked scope (`PROJECT_CONTEXT.md:199-206`) and the silent-omission patterns above; it is a proposed Gate v2 contract, not an osquery guarantee.
