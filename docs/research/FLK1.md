# FLK1: one failure of `test_k3_k4_named_hit_survives_change_and_deadline`

## What the test actually exercises

No failure traceback or failed assertion is recorded in `REVIEWS.md:635-639`. The diagnosis below therefore cannot identify the observed failure, only rank ways the current test can fail. Every explanation of the one observed run is an **inference**.

The first scan writes `first`, measures it, and validates it before calling the fake Defender runner. The runner renames the measured file to `old.bin`, writes `second` at the original name, and returns a valid named hit (`tests/gate_v2/test_m5_round2.py:130-139`). The adapter parses that hit, then its metadata revalidation detects the replacement (`agent/sentinel/gate_v2/defender.py:289-305,327-333`; `identity.py:201-229`). The orchestrator's after-stage hash revalidation retains the evidence while making the result `CHANGED` and its verdict `UNKNOWN` (`orchestrator.py:213-224`). Policy rejects the evidence, gives `UNACCEPTED_DETECTION` and `CHANGED`, and makes the result noncacheable; action policy does not quarantine an unknown verdict (`policy.py:125-134,153-160,185-186,200-202,210-217,248-272`). These are the assertions at test lines 140-143.

The second scan measures the new `second` file. Its fake runner sleeps 30 ms, then returns another named hit, but its request expires 10 ms after construction (`test_m5_round2.py:144-149`). If the runner starts before expiry, the adapter deliberately parses return code 2 and names *before* checking the deadline for negative results (`defender.py:289-315`). The orchestrator may change that result to `TIMEOUT` during its bounded after-stage revalidation, but retains the evidence (`orchestrator.py:218-224`). The final assertion requires only evidence, not a particular status (`test_m5_round2.py:149`).

## Ranked causes and deterministic checks

1. **Very likely: the 10 ms deadline expires before the second runner starts; test fault.** **Inference about the observed run.** The clock starts in `request()` before `scan()` (`test_m5_round2.py:28-31,148`). The scan must measure and hash the path (`orchestrator.py:140-164`; `identity.py:105-180`), then rehash it before a path-opening stage (`orchestrator.py:190-198`; `identity.py:230-240`), then perform a newly constructed adapter's applicability probe on a daemon thread (`defender.py:216-249`), and acquire the process-wide Defender slot (`defender.py:281-289`). The probe waits in 50 ms increments while the entire budget is 10 ms (`defender.py:243-246`). The orchestrator can emit a synthetic `TIMEOUT` before calling the adapter (`orchestrator.py:173-188`); the adapter can also return `TIMEOUT` before the runner (`defender.py:260-277,283-288`). Neither path can contain evidence. **Deterministic reproduction for Claude:** in a temporary local edit to the test, change *only the second* adapter's applicability function to sleep 30 ms before returning `("MpCmdRun.exe", "active")`. Keep the 10 ms request. The final `assert d.engine_results[0].evidence` should fail, and a counter in `late()` should remain zero. This is a reproduction of the race, not proof that this delay occurred in the failed full run. **Fix to the test:** use a fake monotonic clock shared by `scan(clock=...)` and `DefenderAdapter(clock=...)`, and a `ScanRequest` whose `deadline_monotonic_ns` is a small value above the fake clock. Advance that clock past the deadline *inside* `late()` immediately before returning `(2, "Threat : Named.Two")`. Then assert the runner was entered, evidence survives, and the decision is not accepted as malicious. This tests a late returned hit without racing preflight work. Do not alter production deadline checks to make a runner start after its deadline.

2. **Possible: a transient Windows file operation failure in the first runner; external interference/test diagnosis fault.** **Inference about the observed run.** `path.rename(moved)` and `path.write_bytes(b"second")` are unguarded (`test_m5_round2.py:133-137`). A sharing violation, deletion race, or filesystem problem would raise `OSError`, which the adapter converts to `UNAVAILABLE/RUNNER_UNAVAILABLE` and no evidence (`defender.py:320-326`), or the orchestrator may convert an exception to `ADAPTER_ERROR` (`orchestrator.py:207-212`). Any first-half assertion could then fail. The earlier measurement and before-stage rehash close their file handles before the fake runner (`identity.py:118-120,214-229,230-240`), so the code does not appear to hold its own handle across this rename. The unique `tmp_path` makes a leftover `old.bin` from another test unlikely. **Deterministic reproduction for Claude:** locally monkeypatch `Path.rename` for this test's `ordinary.bin` to raise `PermissionError`; the first result has no evidence and is unavailable. **Fix to the test if a traceback supports this cause:** retain the real swap, but record and assert any runner-side filesystem error after `scan()` so the failure identifies the environmental operation. A retry or production change should follow evidence of an actual sharing violation; none is recorded.

3. **Possible but lower: the first scan's five-second deadline expires under a severe pause; test timing fault.** **Inference about the observed run.** The first `request(path)` also starts its deadline before opening and hashing (`test_m5_round2.py:28-31,139`). A pause before the stage yields synthetic `TIMEOUT` with no evidence (`orchestrator.py:173-188`); expiry during applicability or slot acquisition prevents the runner (`defender.py:243-246,260-288`); expiry after the fake runner can make the orchestrator's after-stage check report `TIMEOUT` rather than the expected `CHANGED` (`orchestrator.py:218-224`). **Deterministic reproduction:** delay the first adapter's applicability callback longer than five seconds, or use a controlled clock that crosses the deadline just before the orchestrator's after-stage revalidation. **Fix to the test:** if this is the failed assertion, control the first scan's clock or give that scan an ample deadline; its purpose is replacement identity, not deadline behavior.

4. **Possible only with concurrent scans: the process-wide Defender slot is busy; correct product behavior.** **Inference about the observed run.** `_DEFENDER_SLOT` is module-global (`defender.py:31`) and acquisition is deadline-bounded (`defender.py:281-288`). A separate scan holding it for over 10 ms prevents the second runner from starting. `test_k17_defender_pool_serializes` deliberately exercises that slot but appears later in this file and releases/join its thread in `finally` (`test_m5_round2.py:367-389`). Ordinary pytest runs these tests sequentially; `pyproject.toml:25-26` specifies no parallel runner. Another concurrently running test or leaked thread would be needed. **Deterministic reproduction:** hold `_DEFENDER_SLOT` in a helper thread across the second scan and release it in `finally`; the final evidence assertion fails. **Fix:** same controlled-clock test as cause 1. Do not remove the production semaphore.
