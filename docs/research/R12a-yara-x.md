# R12a — YARA-X v1.22.1 source review

**Scope.** I read the YARA-X v1.22.1 checkout and Sentinel’s current `signatures.py`, `yarafeed.py`, and scan orchestrator. The findings below are source observations unless marked **Inference** or **Gate v2 recommendation**. No files were changed, and no scan or test command was run.

## 1. Architecture

| Component | Role and source evidence |
|---|---|
| `parser/` | Tokenizes and parses rule source into a concrete syntax tree, then builds an AST. The compiler calls `Parser::new`, wraps its stream, and calls `AST::from` in `lib/src/compiler/mod.rs:650-660`; the AST conversion is exposed in `parser/src/ast/mod.rs:54-79`. |
| `lib/` | Main compiler, rule representation, module registry, pattern search, WASM generation, and scan runtime (`lib/Cargo.toml:2-3`; `lib/src/compiler/mod.rs:632-706`; `lib/src/scanner/mod.rs:190-205`). |
| `fmt/` | Rule formatter (`fmt/Cargo.toml:2-3`); the Python `Formatter` wraps it (`py/src/lib.rs:106-175`). |
| `py/` | PyO3 binding that converts Python calls, exceptions, rule objects, matches, and module outputs (`py/Cargo.toml:2-15`; `py/src/lib.rs:483-485,1000-1019,1445-1469`). |
| `capi/`, `cli/` | C API and the `yr` command (`capi/Cargo.toml:2-3,85-86`; `cli/Cargo.toml:2-16`). |
| `proto/`, `macros/` | Module protobuf support and procedural macros (`proto/Cargo.toml:2-3`; `macros/Cargo.toml:2-3`). |
| `js-wasm/`, `ls/` | JavaScript/WASM binding and language server (`js-wasm/Cargo.toml:2-3`; `ls/Cargo.toml:2-17`). |

**Compilation path, with the actual hand-offs:**

| Hop | Function and behavior |
|---|---|
| Python source → Rust compiler | `Compiler.add_source(src, origin)` constructs `SourceCode`, optionally sets its origin, then calls `yrx::Compiler::add_source` (`py/src/lib.rs:565-604`). |
| Parse → AST | Rust `Compiler::add_source` validates UTF-8, runs `Parser::new` and `AST::from`, processes AST items with `c_items`, and records parser/compiler errors (`lib/src/compiler/mod.rs:643-706`). |
| AST → IR | `c_rule` calls `patterns_from_ast`, then `rule_condition_from_ast` (`lib/src/compiler/mod.rs:1683-1694`; implementations in `lib/src/compiler/ir/ast2ir.rs`). |
| Patterns → search structures | `c_rule` extracts atoms and subpatterns (`lib/src/compiler/mod.rs:1995-2020`); `build` constructs the Aho–Corasick automaton (`lib/src/compiler/mod.rs:922-923`). |
| Condition IR → WASM | `c_rule` calls `emit_rule_condition` (`lib/src/compiler/mod.rs:2023-2046`; `lib/src/compiler/emit.rs:1-4,284`). `build` emits WASM bytes and compiles the module for the current platform (`lib/src/compiler/mod.rs:901-917`). |
| Python scan → results | `Scanner.scan` calls Rust `Scanner::scan`; Rust resets scan context, invokes imported modules, evaluates conditions, and returns `ScanResults` (`py/src/lib.rs:1175-1179`; `lib/src/scanner/mod.rs:606-617,643-724,733-747`). Python eagerly converts matching rules and module outputs (`py/src/lib.rs:1445-1469`). |
| Rule → evidence | Python exposes `identifier`, `namespace`, `tags`, metadata pairs, patterns, and each match’s `offset`, `length`, and `xor_key` (`py/src/lib.rs:1242-1339,1472-1539`). Private rules are omitted from the ordinary matching-rule iterator (`lib/src/scanner/mod.rs:897-945`). |

Modules run **only when imported by the compiled rules**; `scan_impl` iterates `ctx.compiled_rules.imports()` (`lib/src/scanner/mod.rs:643-665`). Therefore an empty `module_outputs` entry is not proof that a file was unparsable: the module might never have run (`lib/src/scanner/mod.rs:715-724`; `py/src/lib.rs:1454-1460`).

## 2. Python binding: exact controls and data behavior

| API | Exposed behavior |
|---|---|
| `Compiler(...)` | Constructor flags are `relaxed_re_syntax=False`, `error_on_slow_pattern=False`, `includes_enabled=True`, `ignore_invalid_rules=False` (`py/src/lib.rs:505-542`). `add_source` can be called repeatedly; it raises `CompileError` for the first error unless invalid rules are being ignored. Successfully compiled rules from a source with errors may remain in the final set (`py/src/lib.rs:565-604`; `lib/src/compiler/mod.rs:625-631`). |
| Compiler diagnostics | `errors()`, `warnings()`, and `ignored_rules()` are available; `max_warnings(n)` bounds reported warnings. Ignored reasons distinguish `IgnoredModule`, `IgnoredRule`, and `CompileError` (`py/src/lib.rs:713-717,750-804`). Diagnostic reports serialize `code`, `title`, source location, labels, footers, and rendered text (`lib/src/compiler/report.rs:219-246`). |
| Namespaces, imports, globals | `new_namespace` applies to later sources; includes can be disabled or directed to explicit directories. `define_global` must precede sources using it and accepts Python `bool`, `str`, `bytes`, `int`, `float`, or `dict`; unsupported types raise `TypeError`, invalid definitions `ValueError` (`py/src/lib.rs:606-710`). |
| `Rules` | Holds pinned compiled rules; can iterate rules, list imports, scan bytes with a newly created default scanner, and serialize/deserialize via file-like objects (`py/src/lib.rs:1342-1361,1385-1442`). `Rules.scan()` does **not** offer the persistent scanner’s timeout, cap, globals, console callback, or file-path method (`py/src/lib.rs:1385-1406`). |
| `Scanner` | One scanner can scan sequential inputs; parallel work requires multiple scanners. The Python class is explicitly `unsendable` (`py/src/lib.rs:1000-1007`); it keeps `Rules` alive (`py/src/lib.rs:1008-1033`). **Do not share one Python `Scanner` across threads.** Share compiled `Rules` and construct a scanner for each worker. The Rust build explicitly prepares `Rules` to be shared with scanners in different threads (`lib/src/compiler/mod.rs:839-845`). |
| Per-scan settings | `set_timeout(seconds: u64)`, `max_matches_per_pattern(usize)`, and `fast_scan(bool)` (`py/src/lib.rs:1080-1106`). `fast_scan(True)` can report only a first occurrence when subsequent occurrences are unnecessary to the rule’s boolean condition (`py/src/lib.rs:1095-1104`). |
| Scan-time globals and module data | `set_global` retains its new value across later scans; types must match the compiler definition (`py/src/lib.rs:1036-1077`). `ScanOptions.set_module_metadata` supplies per-scan raw module metadata; `set_module_output` supplies a serialized protobuf that is consumed on the next scan (`py/src/lib.rs:951-997,1128-1172`). A supplied module output replaces module parsing for that scan (`lib/src/scanner/mod.rs:651-667`). |
| Console and results | `console_log(callback)` receives strings from the `console` module; without a callback they are ignored. Callback exceptions are discarded by the binding (`py/src/lib.rs:1109-1125`). Results have `matching_rules` and a dictionary of `module_outputs` (`py/src/lib.rs:1214-1239`). |
| Errors | Python defines `CompileError`, `TimeoutError`, and `ScanError`. Persistent `Scanner` maps Rust timeout specifically to `TimeoutError`; other scan errors become `ScanError` (`py/src/lib.rs:1648-1673`). `Rules.scan()` maps its errors to the generic `ScanError` (`py/src/lib.rs:1388-1405`). File open/map and module failures have separate Rust variants but are all generic Python `ScanError` messages (`lib/src/scanner/mod.rs:51-98`; `py/src/lib.rs:1669-1673`). |

**File memory behavior.** Python `Scanner.scan_file(path)` calls Rust `scan_file` (`py/src/lib.rs:1194-1210`). Rust reads files of at most **32,000,000 bytes** into a `Vec`; above that it defaults to a copy-on-write read-only memory map (`lib/src/scanner/mod.rs:562-603`). This avoids Sentinel first joining a 64 MiB Python `bytes` object. It does **not** make the scan a bounded streaming scan: the mapped file remains the scan input, match tracking consumes memory, and Python eagerly materializes all reported rule/match objects (`lib/src/scanner/mod.rs:108-123`; `lib/src/scanner/matches.rs:242-264`; `py/src/lib.rs:1445-1525`). Rust documents a truncation hazard with mapping and offers `use_mmap(false)`, but that switch is **not exposed** by the Python `Scanner` (`lib/src/scanner/mod.rs:289-303`; `py/yara_x.pyi:264-394`).

**Gate v2 recommendation.** For an ordinary on-disk file, use `Scanner.scan_file()` after a separate bounded, chunked hash and identity check. Run it in an isolated worker for files that another process can change, record the observed file identity before and after, and treat a change as incomplete coverage. For in-memory archive members, use `scan(bytes)` under explicit member and aggregate budgets. The Python binding does not expose Rust’s `max_scan_size` or block scanner (`lib/src/scanner/mod.rs:305-310`; `py/yara_x.pyi:264-394`).

## 3. Modules relevant to files

The stock Python crate enables `console`, `dotnet`, `elf`, `hash`, `lnk`, `macho`, `math`, `pe`, `string`, `time`, and `vt` by default; **`magic` is feature-gated but absent from that default list** (`py/Cargo.toml:20-53`). Check `yara_x.module_names()` at startup for the installed build (`py/src/lib.rs:461-467`). `Module.invoke(data)` directly exposes only `lnk`, `macho`, `elf`, `pe`, `dotnet`, `crx`, and `dex`, takes bytes, and returns `None` if no output is produced (`py/src/lib.rs:57-74,370-437`).

| Module | What it produces; malformed-input behavior; useful gate evidence |
|---|---|
| `pe` | Parses PE headers, sections, imports/exports, resources, Rich header, overlay, and signatures (`lib/src/modules/pe/mod.rs:1-4`; `lib/src/modules/protos/pe.proto:94-160`). On parser failure, output still exists with `is_pe=false` (`lib/src/modules/pe/mod.rs:37-49`). Limits include 96 sections, 16 data directories, 16,384 imports and exports, 65,536 resources, 1,024-byte function names, and 512-byte DLL names (`lib/src/modules/pe/parser.rs:550-556`). Use `is_pe`, entry point, sections, imports, overlay, and individual signature fields; record parser-limit exposure rather than assuming omitted items do not exist (`lib/src/modules/protos/pe.proto:13-16,46-49,137-160`). |
| `pe` Authenticode | `signatures[].verified` is **more than parsing**: the code compares the embedded digest to a computed PE digest, validates the signed-data digest and signer signature, and checks signatures between certificates included in the PE (`lib/src/modules/utils/authenticode.rs:284-304,802-908,954-985`). It stops at a self-signed or externally signed certificate and **does not consult the operating-system certificate store** (`lib/src/modules/utils/authenticode.rs:989-1020,954-966`). Thus `verified=true` means YARA-X’s cryptographic checks passed; it is **not** a Windows trust, revocation, or publisher reputation verdict. The protobuf exposes subject, issuer, validity dates, digest fields, and `verified` (`lib/src/modules/protos/pe.proto:237-273`). |
| `dotnet` | Requires a parseable PE, CLI header, and metadata root, then reads streams such as `#~`/`#-`, `#Strings`, `#US`, `#Blob`, and `#GUID` (`lib/src/modules/dotnet/parser.rs:130-205`). On failure, output has `is_dotnet=false` (`lib/src/modules/dotnet/mod.rs:10-19`). Limits: fewer than 1,000 method parameters, 15,000 rows per table, array dimension 50, recursion depth 16; metadata root caps stream headers at 256 (`lib/src/modules/dotnet/parser.rs:260-264,349-377`). Evidence includes assembly and referenced assemblies, resources, classes, user strings, GUIDs, and type library (`lib/src/modules/protos/dotnet.proto:13-107`). A .NET strong-name field in a header is parsed; this module’s shown path does not establish an OS trust decision (`lib/src/modules/dotnet/parser.rs:322-344`). |
| `lnk` | Validates the `0x4c` shell-link header size and shell-link CLSID, then parses target ID list, link information, strings, and extra data (`lib/src/modules/lnk/parser.rs:31-111`). Important nuance: if the header succeeds but later body parsing fails, it **returns header metadata with `is_lnk=true`** (`lib/src/modules/lnk/parser.rs:89-111`). Use `local_base_path`, `common_path_suffix`, `relative_path`, `working_dir`, `cmd_line_args`, target ID list, tracker data, and overlay fields, with explicit field-presence checks (`lib/src/modules/protos/lnk.proto:118-145`). A target or argument is claimed shortcut content, not evidence that the target exists or was executed (**Inference** from the parser’s byte-only input, `lib/src/modules/lnk/mod.rs:18-27`). |
| `macho`, `elf` | Parse non-Windows executable formats and expose structural fields; parse failure yields an empty protobuf rather than a scan exception (`lib/src/modules/macho/mod.rs:596-606`; `lib/src/modules/elf/mod.rs:29-36`). Mach-O exposes architectures, segments, dylibs, imports/exports, entitlements and certificate data (`lib/src/modules/protos/macho.proto:223-360`). ELF exposes type, machine, segments, sections, and symbols (`lib/src/modules/protos/elf.proto:12-61`). Useful for files encountered on Windows, but not PE substitutes. |
| `hash` | Computes MD5, SHA-1, SHA-256 and related checksums over selected scan ranges; its `main` returns an empty protobuf and clears per-thread caches (`lib/src/modules/hash/mod.rs:15-47`). It is a rule function, not a parser or reputation check. |
| `math` | Supplies math and byte-distribution functions such as entropy; cache thresholds are 4,096-byte ranges and at most eight entries (`lib/src/modules/math.rs:11-26`). Use as a weak quantitative feature, with range and file-size context (**Gate v2 recommendation**). |
| `magic` | Uses libmagic to identify type and MIME; failures return undefined function values (`lib/src/modules/magic/mod.rs:1-5,18-57`). It is not in the Python crate’s default features (`py/Cargo.toml:39-53`), so make it an optional capability. |
| `console` | Rule logging only; `console.log` calls the scanner callback and returns true (`lib/src/modules/console.rs:6-30`; `py/src/lib.rs:1109-1125`). Do not use logged text as an independent detection. |
| `string`, `time` | `string` converts and measures rule strings; parse failures in `to_int` become undefined (`lib/src/modules/string.rs:4-34`). `time.now()` returns current Unix seconds; its value makes a rule’s outcome time-dependent (`lib/src/modules/time.rs:4-26`). |
| `vt` | VirusTotal-context module; its `main` returns an empty `LiveHuntData` protobuf (`lib/src/modules/vt/mod.rs:1-4,52-54`). File, URL, and network context require supplied module output; an ordinary local scan does not acquire VirusTotal facts merely by importing `vt` (`lib/src/scanner/mod.rs:651-667`). Treat supplied context as separately sourced evidence (**Gate v2 recommendation**). |

**Malformed versus absent matters.** `pe`, `dotnet`, and `lnk` give explicit false flags for initial parse failure; `macho`/`elf` give empty objects; a partially parsed LNK may say true. A rule may still match based on other conditions even when structural fields are absent (`lib/src/modules/pe/mod.rs:37-49`; `lib/src/modules/dotnet/mod.rs:10-19`; `lib/src/modules/lnk/parser.rs:103-111`; `lib/src/scanner/mod.rs:708-738`). Gate v2 should persist both the module outcome and the rule outcome.

## 4. Limits and failure semantics

| Condition | YARA-X behavior | Coverage Gate v2 must record |
|---|---|---|
| Timeout | Rust returns `ScanError::Timeout`; Python persistent `Scanner` raises `yara_x.TimeoutError`, with **no `ScanResults` returned**. Timeout is best effort and can overrun the requested period (`lib/src/scanner/mod.rs:208-215,733-747`; `py/src/lib.rs:1169-1179,1669-1673`). | `timeout`, elapsed time, no clean conclusion; do not publish partial rule hits as a completed scan. |
| File open or map failure | Rust distinguishes `OpenError` and `MapError`; Python maps both to `ScanError` (`lib/src/scanner/mod.rs:58-72,562-603`; `py/src/lib.rs:1669-1673`). | `error`, operation and path, bytes/identity examined elsewhere. |
| Module invocation error | Rust returns `ModuleError`, aborting scan rather than returning normal results (`lib/src/scanner/mod.rs:643-665`). | `error`, module name. |
| Module cannot parse format | Normal scan can continue: `pe.is_pe=false`, `dotnet.is_dotnet=false`, `lnk.is_lnk=false`; Mach-O/ELF return empty output (`lib/src/modules/pe/mod.rs:37-49`; `lib/src/modules/dotnet/mod.rs:10-19`; `lib/src/modules/lnk/mod.rs:18-27`; `lib/src/modules/macho/mod.rs:596-606`; `lib/src/modules/elf/mod.rs:29-36`). | `parsed=false` or `fields_absent`, distinct from `module_not_run`; for LNK, `parsed_header=true/body_unknown` is possible (`lib/src/modules/lnk/parser.rs:103-111`). |
| Per-pattern match cap | Default is **1,000,000** accepted matches per pattern. Further matches are rejected and the pattern can be disabled; no cap-hit flag is returned to Python (`lib/src/scanner/matches.rs:255-273,325-348`; `lib/src/scanner/context.rs:2026-2034`; `py/src/lib.rs:1214-1239`). | Configured cap and `cap_possible` when a reported count reaches it. Exact cap exhaustion needs instrumentation or a controlled repeat; count equality alone is not proof. |
| `fast_scan(True)` | Certain patterns stop at the first needed match, so occurrence lists are intentionally incomplete (`lib/src/scanner/mod.rs:233-250`; `py/src/lib.rs:1095-1106`). | `match_offsets_partial=true`, even if rule evaluation completed. |
| Slow pattern | Default is warning; `error_on_slow_pattern=True` makes it a compile error (`py/src/lib.rs:520-542`; `lib/src/compiler/mod.rs:1731-1751,2784-2799`). Literal triggers include one-byte and repeated `00`, `90`, or `FF`; regexp/hex triggers include no atom, atom shorter than two bytes, or more than 2,700 two-byte atoms (`lib/src/compiler/mod.rs:1349-1375,2755-2782`). | Compilation warning code, origin and affected rule; if rejected, record omitted rule count. |
| Other problematic rules | Warning types include `PotentiallySlowLoop`, `TooManyIterations`, `UnsatisfiableExpression`, `MissingMetadata`, and `InvalidRuleName` (`lib/src/compiler/warnings.rs:14-46`). | Diagnostic code and policy decision, separate from scan status. |
| Source has errors | `add_source` returns first error, collects all errors, and can retain successfully compiled rules; `build` returns those rules (`lib/src/compiler/mod.rs:625-631,687-706`; `py/src/lib.rs:565-604,734-760`). | `rules_loaded`, `rules_rejected`, and degraded ruleset status. A nonempty ruleset is not a fully loaded feed. |
| Python file scan size | At 32,000,000 bytes or less, Rust reads the file; above that it memory maps by default. Neither path supplies a Python-level `truncated` indicator (`lib/src/scanner/mod.rs:562-603`; `py/src/lib.rs:1194-1210`). | Full input length, file identity before/after, worker resource outcome. |

There are **no numeric Python return codes** for these conditions. The binding returns a `ScanResults` object or raises the named exception types (`py/src/lib.rs:1175-1210,1648-1673`).

## 5. Rule quality, false positives, and provenance

YARA-X’s slow-pattern warning is a **performance diagnostic**, not a verdict about whether a hit is malicious. Atom selection ranks candidate atoms (`lib/src/compiler/atoms/quality.rs:207-270`); the explicit slow-pattern checks above are the actionable compile-time gates (`lib/src/compiler/mod.rs:1731-1751,2755-2799`). Capture `Compiler.warnings()` and `errors()` before `build()` resets the Python wrapper’s inner compiler (`py/src/lib.rs:734-777`).

[YARA Forge’s package configuration](https://github.com/YARAHQ/yara-forge/blob/master/yara-forge-config.yml) currently sets:

| Package | Minimum quality | Minimum score | Maximum age | Intended Gate v2 treatment |
|---|---:|---:|---:|---|
| `core` | 70 | 65 | 2,500 days | Default candidate feed, still subject to local lint, performance, and benign-file validation. |
| `extended` | 50 | 60 | 5,000 days | Opt-in or deeper investigation tier. |
| `full` | 20 | 40 | 10,000 days | Research tier; require per-rule promotion before it affects a final gate. |

Those are **package selection thresholds**, not measured false-positive rates. The [2026-10-26 release](https://github.com/YARAHQ/yara-forge/releases/tag/20261026) reports 5,128 core, 10,816 extended, and 12,455 full rules; counts vary by release. **Inference:** Sentinel’s current comment equating Forge `score` with specificity is too strong without a calibrated local benign corpus (`sentinel-guard/agent/sentinel/engine/signatures.py:97-109`).

For each hit, retain:

| Field | Source |
|---|---|
| Rule identity | `(namespace, identifier)`, tags, and metadata pairs from the Python `Rule` (`py/src/lib.rs:1242-1283`). |
| Rule provenance | Feed name, release/tag, source URL, source hash, compiler version, build time, and metadata such as `author`, `reference`, `source_url`, `license_url`, `score`, `quality` when present. YARA Forge’s configured metadata order names these fields ([configuration](https://github.com/YARAHQ/yara-forge/blob/master/yara-forge-config.yml)); Python preserves metadata types as strings, bytes, bools, integers, or floats (`py/src/lib.rs:1472-1509`). |
| Match detail | Pattern identifier and bounded `(offset, length, xor_key)` list; store a truncation flag for local evidence limits (`py/src/lib.rs:1286-1339`). |
| Quality decision | Compile warning codes, ignored-rule reason, pack tier, and local validation result (`py/src/lib.rs:750-804`; `lib/src/compiler/warnings.rs:14-46`). |

**Gate v2 recommendation:** treat a Forge score as a *rule authoring and selection attribute*, never as a standalone probability of maliciousness. A high-confidence rule can be strong evidence after provenance and clean-file validation; generic, broad, or ambiguous hits should remain reviewable evidence. A rule match and `pe.signatures[].verified` answer different questions (`py/src/lib.rs:1242-1283`; `lib/src/modules/protos/pe.proto:237-273`).

## Implications for Gate v2

### YARA-X adapter contract

| Contract element | Required value or rule |
|---|---|
| **Input** | File path plus pre/post file identity and chunked SHA-256 for on-disk files; bounded `bytes` for archive members. Record whether YARA saw the complete file or a named region. `scan_file` can reopen/map a path independently of Sentinel’s hash read (`py/src/lib.rs:1194-1210`; `lib/src/scanner/mod.rs:562-603`; `sentinel-guard/agent/sentinel/engine/scanner.py:386-406`). |
| **Ruleset identity** | Hash compiled source or serialized rules plus package release, compiler version, configuration, and accepted/rejected rule manifest. Rule **count** alone is insufficient (`sentinel-guard/agent/sentinel/engine/scanner.py:58-65`; `py/src/lib.rs:1409-1423`). |
| **Status** | `complete_no_hit`, `complete_hit`, `partial_region`, `timeout`, `scan_error`, `rules_unavailable`, `rules_degraded`, `file_changed`, `resource_limit`. A timeout or exception never becomes clean (`py/src/lib.rs:1669-1673`; `sentinel-guard/agent/sentinel/engine/signatures.py:85-94`). These status names are **proposed Gate v2 contract values**, not YARA-X return codes. |
| **Coverage** | Input size, evaluated byte ranges, imported modules, each parser’s state, timeout/cap/fast-scan settings, warning and ignored-rule counts, and whether match details were locally truncated (`lib/src/scanner/mod.rs:643-724`; `py/src/lib.rs:1080-1106,1214-1239`). |
| **Evidence strength** | Rule hit with full provenance and local validation may be strong; Forge score, generic module properties, entropy, or a declared PE certificate are supporting evidence. `pe.signatures[].verified` is cryptographic verification inside the file, not Windows trust (`lib/src/modules/utils/authenticode.rs:284-304,954-966`). This ranking is a **Gate v2 recommendation**. |
| **Provenance** | `(namespace, identifier)`, tags, typed metadata, pattern/offset evidence, ruleset digest, package tier/release, source origin, compile diagnostics, and any local allow/deny policy applied (`py/src/lib.rs:1242-1339,1472-1539`; `py/src/lib.rs:578-604,750-804`). |
| **Performance budget** | Configure separate real-time and deep-scan wall-time and memory budgets; use one scanner per worker, an explicit match cap, and an isolated worker for potentially changing large files. A Python timeout is best effort, so a worker deadline is needed for a hard gate budget (`lib/src/scanner/mod.rs:208-215,289-303`; `py/src/lib.rs:1000-1007`). Exact numerical budgets need measurement on the owner’s Windows workload; the source alone cannot establish safe values. |

### Structure-aware analyzers

Use YARA-X’s `pe`, `dotnet`, and `lnk` parsers as the first structural evidence source. They already expose PE sections/imports/resources/signatures, .NET assembly metadata, and LNK target/argument fields (`lib/src/modules/protos/pe.proto:94-160,237-273`; `lib/src/modules/protos/dotnet.proto:88-107`; `lib/src/modules/protos/lnk.proto:118-145`). For a file-path scan, import those modules in narrowly scoped rules and inspect `ScanResults.module_outputs`; `Module.invoke` is useful for bounded in-memory data but itself requires bytes (`lib/src/scanner/mod.rs:643-724`; `py/src/lib.rs:370-437,1214-1239`). Preserve parser-failure and partial-header states. A separate Windows trust check is still needed if Gate v2 wants to say a PE publisher is trusted (`lib/src/modules/utils/authenticode.rs:954-966`).

**Unresolved by source inspection:** actual Python wheel feature set, Windows peak memory under large Forge rulesets, and time to reach a timeout on the owner’s hardware. `module_names()` and benign synthetic benchmarks on the installed wheel would settle those points (`py/src/lib.rs:461-467`; `lib/src/scanner/mod.rs:208-215`).
