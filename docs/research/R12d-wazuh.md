### Concrete RT-016–RT-018 changes

| Issue | Current Sentinel behavior | Bounded design for Gate v2 / real-time protection |
|---|---|---|
| **RT-016: locked file** | An unreadable scan is not among the two resubmit conditions; an exception only logs. **Sentinel** `agent/sentinel/watcher.py:91-101` | Return a typed `unreadable` reason from the scan gate. For sharing violations or transient access failures, retry with capped exponential delay and jitter, e.g. 0.5, 2, 8, 30 s, a **5-attempt** and **2-minute** ceiling per file generation. Recheck existence, file identity and version before each attempt and before action. On exhaustion, retain `unscanned_locked` as coverage debt and request a later reconciliation; never convert it to clean. This is a proposed policy, not a Wazuh constant. |
| **RT-017: unbounded debounce** | `_pending` is an unrestricted `dict[str, float]`; each event pushes its due time forward, so a continually changing path can starve, and unique paths grow memory. **Sentinel** `agent/sentinel/watcher.py:40`, `agent/sentinel/watcher.py:53-71` | Cap pending paths, e.g. **10,000 globally / 2,000 per root**; store `first_seen`, `last_seen`, `due`, `generation`, and reason. Use both quiet time and a **maximum age** (e.g. 30 s normal; a separately justified partial-file ceiling). At capacity, coalesce by root, mark that root dirty and schedule an incremental reconciliation. Rate-limit worker dispatch; expose pending, coalesced and dropped counters. |
| **RT-018: stop versus action** | `stop()` sets an event but does not join the scan thread; `_run()` checks stop before `_scan_one()`, while `_scan_one()` can call `act_on()` after a long `scan_file()`. The parent stops observer and monitors, then marks `running=False`. **Sentinel** `agent/sentinel/watcher.py:49-51`, `agent/sentinel/watcher.py:73-99`, `agent/sentinel/watcher.py:285-289` | Give each protection run a monotonic **generation ID** and cancellation token. Stop prevents new submissions, cancels pending work, waits for the worker at a defined barrier, and checks the generation again immediately before an automatic action. A scan already running may finish for logging, but its old generation cannot authorize quarantine. Publish “off” only after this barrier; if a bounded join times out, publish a distinct “stopping/action pending” state. |

## 4. Decoders, rules and false-positive tuning

**Matching pipeline.** Analysisd loads decoder and rule XML, decodes an event, selects a rule category, evaluates rule conditions and child/context matches, and queues an alert if the resulting rule has `DO_LOGALERT`. A **level 0** result is ignored as an alert. `src/analysisd/analysisd.c:595-627`, `src/analysisd/analysisd.c:723-768`, `src/analysisd/analysisd.c:2103-2142`, `src/analysisd/analysisd.c:2182-2190`. FIM has a dedicated decoder that produces event-specific data for analysis; rootcheck also has a dedicated decoder. `src/analysisd/decoders/syscheck.c:65-101`, `src/analysisd/decoders/rootcheck.c:25-38`, `src/analysisd/decoders/rootcheck.c:58-94`

| Rule mechanism | Exact behavior useful for Gate v2 |
|---|---|
| `if_sid` versus `if_matched_sid` | `if_sid` builds immediate rule ancestry; `if_matched_sid` uses prior matched-event state for temporal correlation. The parser requires an `if_matched` context when frequency or same/different-field constraints are set. `src/analysisd/rules.c:1653-1678`, `src/analysisd/analysisd.c:2219-2252` |
| `frequency` / `timeframe` | XML frequency must be **2–9999**; the parser internally subtracts 2. Prior events outside `timeframe` stop the search. Correlation is scoped to the same agent unless `global_frequency` is set. `src/analysisd/rules.c:2294-2305`, `src/analysisd/eventinfo.c:142-156` |
| `same_field` | The parser stores dynamic field names; matching requires present, equal values for each named field. Built-in `same_id` and `same_srcip` have separate checks. `src/analysisd/rules.c:1284-1300`, `src/analysisd/eventinfo.c:158-200` |
| Duplicate suppression | A prior event already matched at this rule’s level or higher is not reused for another equal/lower-level correlation. `src/analysisd/eventinfo.c:234-260` |
| `overwrite` and exceptions | A duplicate rule ID is skipped unless `overwrite="yes"`; overwrite without an existing ID is treated as a normal new rule with a warning. `ignore_time` suppresses repeated alerts for a period, and rule-level `NO_AR` prevents active response. `src/analysisd/rules.c:372-388`, `src/analysisd/analysisd.c:2144-2164`, `src/analysisd/rules.c:2380-2385` |

**Lesson for Sentinel:** Gate v2 should emit an evidence-rich verdict and coverage state. A separate action policy decides whether that *specific* finding, file generation and current protection generation authorize notification or quarantine. Sentinel’s handoff already locks this separation in `docs/handoff/PROJECT_CONTEXT.md:131-137`; the present watcher calls `act_on()` directly after scanning at **Sentinel** `agent/sentinel/watcher.py:91-99`. Wazuh’s level is an alert-priority setting and should not become Sentinel’s automatic quarantine threshold. **Inference**, supported by the distinct binding and action stages above.

## Implications for Gate v2 and real-time protection

| Pattern to adopt in user mode | Bounded implementation and harmless verification |
|---|---|
| **Notification plus reconciliation** | Treat create/modify/move as dirty-path hints. Maintain per-root `last_event`, `last_successful_reconcile`, overflow/error counters and a coverage state. Reconcile a bounded number of paths per pass; when event fidelity is lost, report “partial/unverified” until a full pass succeeds. Test with a disposable tree of plain-text files, rapid creates/renames, and an injected overflow/error signal. Wazuh’s scheduled baseline and zero-byte overflow branch motivate this. `src/syscheckd/src/run_check.c:296-314`, `src/syscheckd/src/run_realtime.c:475-515` |
| **Stable identity and typed outcomes** | Key pending work by canonical path plus observed file identity/version where available; revalidate before scan and before action. Store `scanned`, `changed_during_scan`, `locked`, `access_denied`, `vanished`, `too_large/partial`, and `engine_unavailable` separately. A harmless file replaced with different benign bytes between stages should never reuse an earlier clean result. Wazuh’s `fim_get_data()` failure path shows why a read failure must remain visible. `src/syscheckd/src/create_db.c:1414-1422`, `src/syscheckd/src/create_db.c:977-982` |
| **Bounded debounce and retries** | Use the global/per-root caps and maximum ages proposed for RT-017; use the retry budget proposed for RT-016. Exercise repeated harmless writes to one path, more unique benign paths than the cap, and an injected first-attempt sharing failure. Assert finite memory, eventual work or explicit coverage debt, and no clean result from an unreadable file. Current Sentinel due-time reset and retry gaps are at **Sentinel** `agent/sentinel/watcher.py:53-71`, `agent/sentinel/watcher.py:91-101`. |
| **Windowed correlation with scope** | Count distinct file generations or distinct paths in a fixed rolling window, keyed by user directory and event type; separately correlate a Run-value change with a newly observed target. Cap keys and history per key; expire them promptly. Use this for **notify-only** anomaly evidence, with benign bulk rename/build/archive-extraction fixtures to measure false alerts.
