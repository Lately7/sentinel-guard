## 2. One `INSTREAM` scan, end to end

The actual `INSTREAM` path uses **`cl_scandesc_callback`**, because clamd writes the stream to a temporary file; it does not use `cl_scanmap_callback` for this command. `clamd/session.c:613–620`; `clamd/server-th.c:827–846`; `clamd/scanner.c:448–452`.

| Hop | Exact behavior |
|---|---|
| Command | `COMMAND_INSTREAM` creates a temporary descriptor, sets `quota = StreamMaxLength`, then enters `MODE_STREAM`. `clamd/session.c:613–620` |
| Socket framing | `handle_stream()` reads a network-order four-byte length, deducts each chunk from quota, writes payload bytes to the temporary descriptor, and treats a zero-length chunk as completion. A chunk over remaining quota produces `INSTREAM size limit exceeded.` as an error before engine scan. `clamd/server-th.c:817–870,886–890` |
| Dispatch | Completion dispatches `COMMAND_INSTREAMSCAN` to the thread manager. The dispatched connection retains a reference to its engine. `clamd/server-th.c:836–859`; `clamd/session.c:418–433,457–475` |
| Worker | `scanner_thread()` calls `command()`; the `COMMAND_INSTREAMSCAN` branch calls `scanfd(..., stream=1)` and later closes/unlinks the temporary file. `clamd/server-th.c:102–157`; `clamd/session.c:339–362` |
| Public scan API | `scanfd()` calls `cl_scandesc_callback()`. That calls `cl_scandesc_ex()`, which checks the top-level file size, constructs an `fmap`, then calls `scan_common()`. `clamd/scanner.c:429–452`; `libclamav/scanners.c:6440–6466,6487–6556` |
| Per-scan setup | `scan_common()` copies the scan options, allocates the recursion stack, establishes the time deadline and calls `cli_magic_scan()`. `libclamav/scanners.c:5999–6037,6168–6171` |
| Type and dispatch | `cli_magic_scan()` checks limits, determines file type, checks the clean cache, runs raw matching through `scanraw()`/`cli_scan_fmap()`, invokes type-specific parsers, scans extracted or normalized child layers, and performs later raw matching where applicable. `libclamav/scanners.c:4747–4796,4885–4948,4956–5059,5375–5417,5422–5498`; `libclamav/scanners.c:3622–3663` |
| Matchers | `cli_scan_fmap()` selects generic and target roots, reads map chunks, calls `matcher_run()` for each, checks whole-file hashes and evaluates logical/YARA expressions. `matcher_run()` invokes BM, AC, byte comparison, fuzzy image hash and PCRE as applicable. `libclamav/matcher.c:1105–1143,1290–1323,1357–1429,143–260` |
| Result | `scan_common()` selects the last alert and layer verdict; `cl_scandesc_callback()` converts an alerting verdict to `CL_VIRUS`, even if the scan status was an error. `scanfd()` sends `stream: <name> FOUND`, `stream: <error> ERROR`, or `stream: OK`. `libclamav/scanners.c:6228–6233,6477–6484`; `clamd/scanner.c:461–477`; `clamd/session.c:145–172` |

`cl_scanmap_callback()` is a parallel public entry point for an already supplied map. Its top-level size check has the same clean-or-alert behavior as the descriptor entry point; it is not the INSTREAM hop. `libclamav/scanners.c:6569–6613,6616–6650`.

## 5. Limits and error paths

### Limit table

“May be `OK`” means **if no other alert or terminal error occurs**. It does not mean the omitted content was judged clean. `AlertExceedsMax` is wired to `CL_SCAN_HEURISTIC_EXCEEDS_MAX` at `clamd/server-th.c:1196–1206`; it affects only code paths that call the corresponding heuristic append function or the explicit top-level size branch.

### Other success-producing gaps and errors

There is an important distinction between **a parser returning an error** and **the whole scan returning an error**. `result_should_goto_done()` explicitly converts `CL_EFORMAT`, `CL_EPARSE`, `CL_EREAD`, `CL_EUNPACK`, all `CL_EMAX*`, and otherwise unlisted results to `CL_SUCCESS` so scanning can continue. It also converts `CL_ETIMEOUT` to success while halting. By contrast, the listed terminal I/O/memory/temp-file failures are propagated. This is a generic rule across parsers, not an exhaustive enumeration of every parser statement. `libclamav/scanners.c:4415–4499`.

| Condition → location | Potential INSTREAM result | Coverage meaning |
|---|---|---|
| Malformed/truncated ZIP records produce `CL_EPARSE`/`CL_EFORMAT` in the ZIP parser. `libclamav/unzip.c:646–661,932–972,1332–1379` | May be `OK` after generic result filtering. `libclamav/scanners.c:4483–4495`; `clamd/scanner.c:469–477` | ZIP members that could not be enumerated/extracted are not certified clean. |
| PDF stream with found start but no end reports `CL_EFORMAT`; another PDF path explicitly calls a truncated object `CL_SUCCESS`; a PDF parse error is explicitly reset to success in one handler. `libclamav/pdf.c:209–273,702–717,1700–1710` | May be `OK`. | Raw bytes may have been matched, but extracted PDF objects/streams may be absent. |
| Nested map request extending beyond parent is truncated to available bytes; a tiny or invalid bounded submap can return `CL_SUCCESS` without scanning. `libclamav/scanners.c:5786–5808` | May be `OK`. | Requested embedded object was shortened or skipped. |

## 6. Concurrency and reload

`clamd` creates a worker pool with configured `MaxThreads`, `IdleTimeout` and `MaxQueue`; each dispatched scan holds a reference to the engine pointer copied into its connection. The Sentinel config sets `MaxThreads 4`; the parser’s `MaxQueue` default is 100 unless configured. `clamd/server-th.c:1412–1413,1540,1567,1663`; `clamd/session.c:418–433`; `common/optparser.c:340–352`; `agent/sentinel/engine/clamav.py:90–94`.

`RELOAD` replies `RELOADING` after setting a flag; that response is **not** evidence that the new database has loaded. The reload thread creates a new engine, copies settings, loads and compiles the database, then publishes it. With `ConcurrentDatabaseReload` enabled (the option parser’s default), clamd keeps scanning on the old engine until activation, swaps the active pointer and releases the old engine only after outstanding references finish. On load failure, it keeps the prior engine. With concurrent reload disabled, it clears the active engine and waits for scans before loading. `clamd/session.c:571–581`; `clamd/server-th.c:219–285,298–304,330–368,1766–1806`; `common/optparser.c:366`.

`VERSION` prints the version and database version/time from the **engine attached to that connection**. Therefore a version request before activation can report the old database, while a later request can report the new one; a separate `VERSION` request is not a per-scan proof of which generation evaluated another connection. Sentinel caches the string for 60 seconds and uses it in its scanner identity, increasing the possible mismatch interval around reload. `clamd/session.c:484–499,588–593`; `clamd/server-th.c:1663,1787–1800`; `agent/sentinel/engine/clamav.py:318–325`; `agent/sentinel/engine/scanner.py:58–64`.

## Implications for Gate v2

1. **Treat `stream: OK` as “no ClamAV alert on paths that executed,” not proof of complete coverage.** At minimum, the gate must represent: top-level or nested file-size omission; cumulative size/file-count/recursion/time exhaustion; specialized embedded-PE, HTML, script, ZIP-type, partition, icon, HWP and PCRE omissions; parser failures and unsupported handlers; and a deliberately truncated Sentinel stream. The source-supported distinctions are in the limit and error tables above. Sentinel currently converts `OK` directly to `clean` (`agent/sentinel/engine/clamav.py:217–227,328–345`) and truncates files over 400 MiB to their first 400 MiB (`agent/sentinel/engine/clamav.py:308–316`).

2. **Set `AlertExceedsMax yes` and keep `HeuristicScanPrecedence no`.** This makes the shared `MaxScanSize`, `MaxFileSize`, `MaxFiles`, `MaxRecursion` and `MaxScanTime` checks observable as `Heuristics.Limits.Exceeded.*` alerts where the engine appends them; it does **not** expose every specialized skip. Sentinel should map those names to `coverage=incomplete`, not to malware or automatic quarantine. `clamd/server-th.c:1196–1206,1350–1352`; `libclamav/others.c:1197–1213,1235–1259,1296–1320,1787–1795`; `agent/sentinel/engine/clamav.py:108,229–233`.

3. **Make the configured scan budget an explicit contract.** Record `StreamMaxLength`, `MaxFileSize`, `MaxScanSize`, `MaxFiles`, `MaxRecursion`, `MaxScanTime`, the specialized limits and relevant parser switches with each scan policy revision. Sentinel’s current `MaxScanSize 1600M` allows a 400 MiB outer input to consume the remaining budget quickly through extracted children; it is a bounded scan, even when `stream: OK` returns. `agent/sentinel/engine/clamav.py:94–109`; `libclamav/others.c:1235–1265`; `libclamav/default.h:34–59`.

4. **Parse ClamAV names as typed evidence.** Add `BC.Heuristics.` to Sentinel’s heuristic category, and separate `Heuristics.Limits.Exceeded.*` from malware findings. Preserve the raw name, engine version, database version and configuration identity. A `FOUND` reply is also not a completeness guarantee because an alert can mask a scan error at the public API boundary. `libclamav/others.c:1721–1741`; `libclamav/scanners.c:6477–6484`; `agent/sentinel/engine/clamav.py:229–233`.

5. **Do not use `RELOADING` or a nearby `VERSION` call as scan-generation attestation.** Invalidate cached verdicts across an update, wait until the active `VERSION` changes before advertising the new database, and bind a scan to a generation only if the integration can establish it on the same engine/session. The current clamd text protocol supplies no generation field in the INSTREAM reply. `clamd/session.c:571–593`; `clamd/scanner.c:461–477`; `clamd/server-th.c:1787–1800`; `agent/sentinel/engine/clamav.py:318–325`.

6. **Expose uncertainty instead of inventing precision.** INSTREAM gives Sentinel `FOUND`, `ERROR` or `OK`, and optional limit names if enabled. It does not return a per-parser coverage ledger. Gate v2 can mark known boundaries as incomplete from its own input size/configuration, mark alerted limits incomplete from reply names, and classify an otherwise successful ClamAV result as “bounded scan completed with unobservable parser/feature omissions possible.” Stronger guarantees would require instrumenting libclamav or obtaining per-layer metadata through an integration beyond the present INSTREAM client. `clamd/scanner.c:461–477`; `libclamav/others.c:1203–1211`; `libclamav/scanners.c:6126–6165,6190–6197`; `agent/sentinel/engine/clamav.py:217–227`.
