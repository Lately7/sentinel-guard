## 2. Rule YAML and semantics

A rule has `rule.meta` and one top-level statement under `rule.features`. Both `meta.scopes.static` and `meta.scopes.dynamic` are required; either can be `unsupported`. Static scopes are file, function, basic block, and instruction; dynamic scopes are file, process, thread, span of calls, and call. `global` denotes features available at every scope, not a rule’s analysis scope. `capa/rules/__init__.py:84-119`, `capa/rules/__init__.py:122-176`, `capa/rules/__init__.py:1177-1209`.

| YAML construct | Meaning and consequence | Source |
|---|---|---|
| `and`, `or`, `not` | All children, any child, or inverted child result. Evaluation normally short-circuits. | `capa/rules/__init__.py:847-866`; `capa/engine.py:99-178` |
| `N or more`, `optional` | At least N child statements. `optional` is `0 or more`, so it can document supporting observations but **cannot be required evidence**. | `capa/rules/__init__.py:867-882`; `capa/engine.py:181-220` |
| `count(feature)` | Counts the feature’s distinct recorded locations against an exact number, minimum, maximum, or interval. It is not a count of executions unless the extractor’s locations represent events. | `capa/rules/__init__.py:642-711`; `capa/engine.py:223-240` |
| `match: rule name` or namespace | Consumes an earlier rule match. A namespace reference can cover rules under that namespace; dependencies are ordered before their consumers. Subscope statements are converted into generated rules before matching. | `capa/rules/__init__.py:1024-1066`, `capa/rules/__init__.py:2014-2054`; `capa/engine.py:280-299` |
| `meta` | `namespace` organizes results; `att&ck` and `mbc` are taxonomy mappings; `lib: true` marks a reusable building block. `maec/*` may name category, family, or analysis conclusion. These are **rule-author annotations**, not independent evidence supplied by ATT&CK, MBC, or MAEC. | `capa/rules/__init__.py:58-75`; `capa/render/result_document.py:562-689`; examples at `../capa-rules/lib/write-process-memory.yml:1-6` and `../capa-rules/communication/c2/file-transfer/download-and-write-a-file.yml:1-5` |

## 4. Safe use in Sentinel

**Yes, with a restricted scope:** run the trusted capa executable or isolated Python environment as a separate child **against a static PE file**, using a pinned rule set and `-j`. The vivisect and dnfile paths parse and analyze bytes; they do not invoke the scanned file as a Windows program. That is a conclusion about the inspected capa paths, not a guarantee about all optional backends or dependencies. `capa/loader.py:238-311`, `capa/loader.py:351-357`, `capa/main.py:583-602`.

A critical v10.0.0 boundary is `.viv` workspace loading. By default, an adjacent `.viv` is ignored; `CAPA_LOAD_VIV_WORKSPACE=1` permits loading it through pickle-backed workspace deserialization. Sentinel should set a controlled child environment that leaves that variable unset, as well as `CAPA_SAVE_WORKSPACE`. `capa/loader.py:77-82`, `capa/loader.py:201-235`; `capa/main.py:862-868`. The [v10.0.0 release note](https://github.com/mandiant/capa/releases/tag/v10.0.0) identifies the prior workspace-loading security issue.

**Input identity matters.** Sentinel has already hashed bytes for its scan, but capa’s CLI reopens the path and computes its own hash. If the path can change between those operations, Sentinel must either give capa an immutable snapshot of the already scanned bytes or reject the explanation when the returned SHA-256 differs. This is an integration inference from capa’s `path.read_bytes()` and emitted sample hash, and Sentinel’s stated exact-byte scan contract. `capa/features/extractors/viv/extractor.py:43-47`; `capa/loader.py:679-712`; `PROJECT_CONTEXT.md:62-64`.

For a bounded child on Windows, an argv-array invocation with `shell=False` can use Python’s timeout handling, while a Windows Job Object can impose a job-wide committed-memory limit and terminate the associated process tree when closed. A Python timeout alone does not impose a memory ceiling, and Python documents that initial process creation may outlast the nominal timeout. These are platform facts from the [Python subprocess documentation](https://docs.python.org/3/library/subprocess.html) and [Microsoft Job Object limit documentation](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information). The parent must also cap captured stdout/stderr; `capture_output=True` by itself buffers output without an application-size limit. [Python subprocess documentation](https://docs.python.org/3/library/subprocess.html).

## Implications for Gate v2 — optional explanation-stage contract

The owner’s locked decision is “capa optional, explanation only, later”; Gate v2’s scan status and verdict must remain separate. `PROJECT_CONTEXT.md:112-125`.

| Contract field | Proposed value |
|---|---|
| **When** | After Sentinel has established the file’s scan identity and decided its own verdict, request capa **asynchronous explanation** only for eligible native or .NET PE files where additional technical detail is useful. Do not place completion of this optional work on the safety decision’s critical path. This is a design proposal grounded in the locked decision and capa’s PE/.NET backend selection. `PROJECT_CONTEXT.md:112-125`; `capa/main.py:583-602` |
