# RED5 — feeds, indicators, and rule publishing

These are in-process regression tests for Claude to run. They were read against the current code; pytest was not run in this round. No installed service, network, Defender settings, or malware samples are involved.

## High — nonempty truncated feed replaces prior protection

**Attacker model:** broken or hostile feed response. **Steps:** publish 20 host indicators from one source, then return a one-line response. **Effect:** the update is reported `ok (1)`, and 19 previously blocked hosts become unknown. **Lines:** `agent/sentinel/feeds.py:164-174` rejects only zero parsed entries; `:280-286` labels the one-line response successful; `agent/sentinel/indicators.py:63-76,95-112` rebuilds the snapshot from only the new rows. **Fix:** compare each source's new cardinality and content against its prior snapshot, quarantine anomalous drops for review, and carry the old source rows forward until accepted. **Evidence:** proven by `test_red5_truncated_nonempty_feed_keeps_previous_indicators`.

## High — duplicate URLs lose source ownership

**Attacker model:** one feed stops responding after two sources listed the same malicious URL. **Steps:** publish the same URL from both sources, delist it in the first, and fail the second. **Effect:** the shared-platform URL disappears despite the second source's previous listing. The same schema pattern applies to hashes. **Lines:** `agent/sentinel/indicators.py:35-40` gives `urls` and `hashes` primary keys without `source`; `:80-88` inserts with `OR IGNORE`; `:207-218` carries over only rows recorded for the failed source; `agent/sentinel/feeds.py:280-290` rebuilds from those rows. **Fix:** key URLs and hashes by `(indicator, source)` and derive the highest priority lookup row, as already done for hosts. **Evidence:** URL effect proven by `test_red5_duplicate_url_sources_survive_one_feed_failure`; hash effect inferred from the identical primary-key pattern.

## High — a missing published file is reported healthy

**Attacker model:** power loss, disk failure, or file disappearance between updates. **Steps:** publish a snapshot, remove the file after closing its handle, then ask the reader about health. **Effect:** host lookups become empty while `healthy()` returns true; `check_and_repair()` therefore leaves the stale pointer intact, and a recent successful feed status delays rebuilding. **Lines:** `agent/sentinel/indicators.py:140-155` leaves `_conn` null for a missing target; `:243-250` treats every null connection as healthy; `agent/sentinel/db.py:248-255` relies on that health result; `agent/sentinel/feeds.py:230-237` uses previous update time. **Fix:** distinguish “never published” from “published but absent/unreadable”; flag degraded protection and force a rebuild or recover a verified prior snapshot. **Evidence:** missing-file health error proven by `test_red5_missing_published_snapshot_is_unhealthy`; retry delay inferred from the cited schedule.

## High — concurrent publish cleanup can delete the winning snapshot

**Attacker model:** two legitimate publishers race, including feed publication and legacy migration. **Steps:** pause publisher A just before cleanup, let B commit and close its reader, then resume A. **Effect:** A deletes B's file even though the state DB points to B, leaving empty protection on the next open. **Lines:** `agent/sentinel/indicators.py:254-262` commits before cleanup; `:265-274` deletes every snapshot except the caller's path without rereading the committed pointer; `agent/sentinel/db.py:298-312` calls `publish()` for migration outside the feed mutex, while `agent/sentinel/feeds.py:240-255,304` protects only feed updates. **Fix:** serialize all publishers or have cleanup read the current committed pointer and preserve it, preferably preserving a verified prior generation too. **Evidence:** proven by `test_red5_stale_publish_cleanup_keeps_newest_snapshot` under the forced interleaving.

## High — malformed Tranco rows can become an accidental allow-list

**Attacker model:** broken or hostile popularity archive. **Steps:** serve an archive with 50,000 copies of the same rank and blocked host. **Effect:** the parser accepts this as a sufficiently long top list, marks that host popular, and removes its block row during the next publish. **Lines:** `agent/sentinel/feeds.py:119-145` checks line count but not rank, uniqueness, or domain format; `:265-278` installs the resulting set; `:167-174,190-204` excludes popular hosts from fresh and carried rows. **Fix:** require consecutive unique ranks, unique valid domains, and plausible list cardinality before adopting a new popularity snapshot. **Evidence:** proven by `test_red5_repeated_tranco_rows_cannot_allow_blocked_host`.

## Medium — YARA worker trial accepts a match on empty input

**Attacker model:** compromised or defective rule package. **Steps:** provide a compilable `condition: true` rule; the trial worker reports a completed scan that matched empty bytes. **Effect:** the rule file is installed despite matching every subsequent scan, causing broad false alerts and potential actions under combined evidence. **Lines:** `agent/sentinel/yarafeed.py:62-79` checks identity, status, and readiness but never the trial verdict or evidence; `:135-164` installs after the trial; `agent/sentinel/gate_v2/rules.py:276-295` creates evidence for matching rules. **Fix:** reject candidate packs that match empty input or a small benign corpus, and retain the previous file. **Evidence:** acceptance of a suspicious empty-input worker result proven by `test_red5_yara_trial_rejects_match_on_empty_input`; the on-disk action consequence is inferred.

## Other probes

Host parsing rejects non-ASCII look-alike hostnames and NUL-tainted host tokens through `_HOST_RE` (`feeds.py:85-95`). The bounded fetch and archive reads cap bytes (`feeds.py:148-158`, `yarafeed.py:120-134`), though large within-limit lines were not claimed as a finding without a demonstrated failure. Invalid UTF-8 is replaced during decoding (`feeds.py:157-158`, `yarafeed.py:133`); a replacement character inside a host fails the host regex. Snapshot pointer and generation update in one state DB transaction (`indicators.py:254-259`), so a crash between those two metadata writes does not split them. A crash before pointer commit leaves the old pointer; a power loss after commit still needs the missing-file check above. A replaced snapshot has no content digest check (`indicators.py:140-155`), but installed-state ACL verification (`service/installer.py:748-805`) did not establish a medium-integrity swap path. No rollback-specific finding was claimed: ordinary feed publication does not select an older generation, and this round did not establish a medium-integrity path to modify protected installed state.
