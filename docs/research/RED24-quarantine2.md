# RED24: quarantine, second pass

Tests: `tests/codex/test_red24_quarantine2.py`. They use the harmless marker, `tmp_path`, and the `SENTINEL_HOME` fixture. They were reviewed against the code and **not run** in this round. RED1's findings are excluded.

## High — failed post-delete status query discards the only copy

**Test:** `test_red24_post_delete_status_failure_keeps_the_only_copy`. **Attacker model:** transient filesystem or storage failure at the worst moment. **Steps:** quarantine writes and syncs the blob, records it, marks the original for deletion, and closes the deleting handle. The final `watch.survives()` call then raises `TargetError`, as its Windows status query can do. The outer exception handler removes the database row and unlinks the blob even though the original's name has already gone. **Effect:** the only recoverable copy is lost. **Lines:** `agent/sentinel/quarantine.py:195-205, 218-230`; `agent/sentinel/gate_v2/winfile.py:191-211`. **Fix:** once deletion may have occurred, retain the synced blob and journal on an inconclusive status check; settle it by recovery rather than rolling back the only copy. **Evidence:** inferred from the code; the test injects the status failure after the real handle deletion and is unrun.

## High — restore retires the held copy before syncing the output

**Test:** `test_red24_restore_syncs_output_before_removing_record`. **Attacker model:** power loss or storage failure during an approved restore. **Steps:** restore decodes into a newly created file, checks SHA-256, and commits removal of the quarantine row before closing the output. It never flushes and `fsync`s that output; it then unlinks the previously synced blob. A power cut can leave neither a durable restored file nor a retained copy. **Effect:** loss of the only copy despite a successful restore response. **Lines:** `agent/sentinel/quarantine.py:321-345`; compare the explicit blob flush and `fsync` at `agent/sentinel/quarantine.py:107-113`. **Fix:** flush and sync the restored file before retiring its record or blob, and make completion recoverable across the database and unlink boundary. **Evidence:** inferred power-cut consequence; the unrun test records file sync calls and checks their order at row removal.

## Medium — filename encoding collides with real private-use characters

**Test:** `test_red24_private_use_filename_round_trips`. **Attacker model:** a downloaded file with a crafted NTFS name containing literal U+F0000. **Steps:** `kept_path()` leaves that character unchanged in the database, while `real_path()` always converts U+F0000 through U+F07FF into lone surrogates. Quarantine removes the correctly named original; restore decodes the stored path to a different name. **Effect:** restore places a file at an unexpected path, and the original name is not recovered. **Lines:** `agent/sentinel/quarantine.py:47-57, 201-203, 313-319`. **Fix:** use an injective path encoding that escapes both surrogates and its escape range, or store original UTF-16 code units in a reversible form. **Evidence:** direct code inference; the unrun test performs a quarantine and restore using the literal private-use character.
