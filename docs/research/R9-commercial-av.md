# R9 — Publicly documented decision systems and Gate v2 implications

**Scope.** This is a read-only review of the repository and public product material. I did not run a scan or test suite, inspect proprietary code, or obtain samples. Product features vary by edition, licence, policy, and version; consumer and enterprise features are identified separately below.

**A limit on “exact pipeline order.”** None of the vendors publishes a complete, versioned decision tree for every file. Real-time checks, cloud queries, and behavior monitors can run concurrently or only on particular triggers. The sequences below describe the documented decision points, not an asserted universal call order. Likewise, a detection name generally identifies a category or originating subsystem; it is **not** a published probability of maliciousness.

## 1. Malwarebytes — deepest public account

### Pipeline and decision points

| Stage | Publicly documented mechanism | What it establishes |
|---|---|---|
| Before or at file launch | **Malware Protection** prevents detected malicious programs from launching. **Decision policy.** Public material does not disclose a consumer threshold that fuses signatures, ML, emulation, signer, prevalence, and behavior into one score. `MachineLearning/Anomalous.100%` means maximum *deviation from the vendor’s legitimate training set* in that detector’s naming scheme; it is not a 100% malware probability. Malwarebytes says recognized legitimate files can be submitted for whitelisting. `Generic.Malware/Suspicious` is a generic criteria based detection, and Malwarebytes says real-time protection can block it: the word “Suspicious” in the name therefore does not imply “notify only.” `PUP` and `PUM` have explicit **Ignore / Warn / Treat as malware** scan settings. [Anomalous name](https://www.malwarebytes.com/blog/detections/machinelearning-anomalous-100), [generic name](https://www.malwarebytes.com/blog/detections/generic), [scan settings](https://help.malwarebytes.com/hc/en-us/articles/41813847845275-Malwarebytes-for-Windows-scan-settings).

**Remediation scope.** `PUM.Optional.UserWLoad`, for example, denotes a potentially unwanted Windows registry modification. Historical Malwarebytes enterprise material names a **Linking Engine** for artifacts associated with a primary payload. Current EDR documentation establishes observation of processes, registry, files, and network activity, but does **not** publish a complete algorithm proving that every scheduled task, service, or dropped file is always removed. Those object classes should not be promised merely from the “Linking Engine” description. [PUM example](https://www.malwarebytes.com/blog/detections/pum-optional-userwload), [EDR actions](https://support.threatdown.com/hc/en-us/articles/4413799273363-Perform-actions-on-suspicious-activities), [historical linking description](https://prod-www-dynamic.malwarebytes.com/pdf/datasheets/IncidentResponseSolutionBrief.pdf).

## 2. Microsoft Defender Antivirus and adjacent Windows controls

| Phase | Documented mechanism and decision |
|---|---|
| Before execution | Local security intelligence, heuristics, and local ML operate alongside cloud-delivered protection. **Block at first sight** applies to Internet-origin executable and non-PE files: it checks the hash, may hold an unresolved file, submit a copy, then allow or block on the cloud determination. Its default hold is **10 seconds**, configurable by adding **0–50 seconds** for at most **60 seconds**. Cloud blocking levels include Default, High, High Plus, and Zero Tolerance; Zero Tolerance blocks unknown executables. These are policy modes, not disclosed numerical malware scores. Defender’s scan troubleshooting page says scans initiated from the Defender portal or Windows Security app have **no time limit**. [Scan types](https://learn.microsoft.com/en-us/defender-endpoint/schedule-antivirus-scans), [scan exclusions and full scope](https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-exclusions-overview), [Offline scan](https://learn.microsoft.com/en-us/windows/security/threat-protection/microsoft-defender-antivirus/microsoft-defender-offline), [scan troubleshooting](https://learn.microsoft.com/en-us/defender-endpoint/troubleshoot-mdav-scan-issues).

**Failure behavior.** Microsoft explicitly says disabling cloud-delivered protection limits analysis to local ML and similar client functions; that establishes a local fallback, **not** equal protection or a promise that every unresolved file is held indefinitely. Archive size and scan settings are configurable. Public documentation reviewed does not give one universal “clean versus unscanned” result contract for all encrypted, oversized, timed-out, and engine-failure cases. A local clean result under a configured exclusion means the excluded object was **skipped**, because Defender says matching exclusions skip scanning. [Cloud and local analysis](https://learn.microsoft.com/en-us/defender-endpoint/cloud-protection-microsoft-antivirus-sample-submission), [scan options](https://learn.microsoft.com/en-us/defender-endpoint/troubleshoot-mdav-scan-issues), [exclusions](https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-exclusions-overview).

**Naming.** Microsoft’s public CARO scheme is `Type:Platform/Family.Variant!Suffix`. Type and platform have published meanings; the family may be generic. Microsoft says a `!` suffix is an **internal indicator** and does **not** define `!ml`, `!MTB`, or `!rfn` publicly as confidence thresholds. Those suffixes must not drive Gate v2 quarantine policy. [Microsoft malware naming](https://learn.microsoft.com/en-us/defender-xdr/malware-naming?view=o365-worldwide).

## Design lessons for Sentinel Guard Gate v2

### Current code facts relevant to the design

| Current fact | Evidence and consequence |
|---|---|
| The current `Verdict.label` returns malicious for any `CRITICAL` finding **or** summed score `≥70`, suspicious at `≥30`, otherwise clean. It does not consult engine status or coverage. | `agent/sentinel/engine/verdict.py:32-72`. A timeout or uninspected file can therefore have the top-level label `clean`. |
| ClamAV currently maps `Heuristics.*` and `PUA.*` to `MEDIUM`/30, and every other returned name to `CRITICAL`/100. | `agent/sentinel/engine/clamav.py:228-233`. The observed weak `Win.Trojan.Suspect-34` case in the locked context requires a more specific policy; names alone do not reveal the underlying signature mechanism. |
| `AlertEncrypted no` and `AlertExceedsMax no` are generated in clamd configuration. An `OK` reply becomes `"clean"` without internal coverage evidence. | `agent/sentinel/engine/clamav.py:96-109`, `agent/sentinel/engine/clamav.py:217-225`, `agent/sentinel/engine/clamav.py:328-344`. |
| ClamAV streams at most the first **400 MiB** of a larger file and labels a no-hit result partial. YARA/rules on an oversized file use first **64 MiB** plus last **8 MiB**. The core archive budgets are depth **3**, **2,000** members, **256 MiB** total expanded content. | `agent/sentinel/engine/clamav.py:38-39`, `agent/sentinel/engine/clamav.py:310-316`, `agent/sentinel/engine/scanner.py:23-25`, `agent/sentinel/engine/scanner.py:189-218`, `agent/sentinel/config.py:14-17`. ### What to copy, and what the architecture cannot copy

| Copy into Gate v2 | Why | Limit |
|---|---|---|
| **Typed per-engine status, coverage, and provenance.** Distinguish completed negative inspection from partial, skipped, unavailable, timeout, and error. | Multiple products explicitly expose skipped encrypted or inaccessible content; current Sentinel top-level clean does not encode that distinction. `agent/sentinel/engine/verdict.py:62-72`; [Bitdefender skipped items](https://www.bitdefender.com/consumer/support/answer/1976/), [Sophos EFS limit](https://docs.sophos.com/esg/endpoint/help/en-us/help/Scan-from-CLI/index.html). | Coverage means “what this engine inspected under this version/configuration,” not “file is safe.” |
| **Separate malware, PUA, suspicious, and scan-health decisions.** | Malwarebytes exposes PUP/PUM actions; Sophos separates ML malware and ML PUA; Kaspersky has probably infected objects. [Malwarebytes settings](https://help.malwarebytes.com/hc/en-us/articles/41813847845275-Malwarebytes-for-Windows-scan-settings), [Sophos PUA](https://docs.sophos.com/central/customer/help/en-us/ManageYourProducts/Alerts/ThreatAdvice/DealPUAs/DealPUAAlerts/index.html), [Kaspersky status](https://support.kaspersky.com/ksc/14/en-US/158852.htm). | Gate v2’s locked four verdicts remain `clean/suspicious/malicious/unknown`; encode PUA as a separate category/evidence channel without silently equating it to malware. |
| **Independent decision and action policies with reason codes.** | Commercial products expose report/audit/warn/block/quarantine modes independent of detector names. [Bitdefender HyperDetect](https://www.bitdefender.com/business/support/en/77209-342938-hyperdetect.html), [Microsoft ASR](https://learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/enable-attack-surface-reduction). | A name prefix or summed score should not be an irreversible action rule. |
| **Versioned exceptions and false-positive feedback.** | Restore, allow, exclusions and vendor reclassification are distinct operations in public product workflows. [Malwarebytes quarantine](https://help.malwarebytes.com/hc/en-us/articles/31589479169179-Manage-quarantined-items-in-Windows-and-Mac), [ESET exclusions](https://help.eset.com/eea/13/en-US/idh_detection_exclusion.html). | The owner has locked Restore to a path+hash exception; broad Trust is a separate explicit act. `docs/handoff/PROJECT_CONTEXT.md:139-142`. |
| **A genuinely different smart and deep scope.** | Major products’ quick scans include startup, memory, process or boot surfaces; deep/full scans extend scope and sometimes methods. [Microsoft scopes](https://learn.microsoft.com/en-us/defender-endpoint/schedule-antivirus-scans), [Sophos scopes](https://docs.sophos.com/esg/endpoint/help/en-us/help/Scan-Computer/index.html). | Sentinel’s locked user-mode smart scope is readable startup/Run/task/process **image paths**, not process memory or boot sectors. `docs/handoff/PROJECT_CONTEXT.md:199-206`. |

A no-admin Python watcher cannot promise synchronous pre-open blocking, kernel/driver or bootkit observation, process-attributed ransomware rollback, protected tamper resistance, or commercial-scale prevalence and cloud sandbox decisions. Microsoft’s filesystem minifilter model explains the privileged file-I/O interception boundary; ThreatDown explicitly lists drivers supporting its EDR flight recorder and rollback. [Microsoft minifilters](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/about-file-system-filter-drivers), [ThreatDown components](https://support.threatdown.com/hc/en-us/articles/38204090818579-Endpoint-Agent-system-components). **Inference:** Gate v2 should report post-write detection honestly and never imply that a scan result prevented a file from running.

### Recommended exact Gate v2 verdict and action rules

The following is a **proposed policy**, constrained by the owner’s locked decisions. “Trusted clean” is a separate boolean from the four-state verdict. The table gives precedence; evaluate rows top to bottom.

| Precedence | Condition | `verdict` | `trusted_clean` | Default `evidence-v1` action and reason |
|---:|---|---|---:|---|
| 1 | An authenticated engine reports an accepted **conclusive** detection for the same verified file generation: known-bad hash; critical **user** rule pack; Defender named threat; or ClamAV detection outside the weak-name policy. | `malicious` | `false` | Auto-quarantine if enabled and the target still matches its recorded identity/hash; `CONCLUSIVE_LOCAL`, `DEFENDER_THREAT`, or `CLAMAV_CONCLUSIVE`. Partial coverage elsewhere does not cancel this detection. EICAR is handled the same way and labelled as a test file. |
| 2 | ClamAV’s daemon identity cannot be verified, although it reports a detection. | `suspicious` unless independent conclusive evidence exists | `false` | Notify; `UNVERIFIED_CLAMD`. An unverified `OK` contributes no clean coverage. |
| 3 | No conclusive hit; one YARA Forge match, weak ClamAV name, PUA/PUM, nonconclusive ML/heuristic, or a documented **corroborated** combination of independent strong signals. | `suspicious` | `false` | Notify and offer review; `WEAK_DETECTION` or `CORROBORATED_SIGNALS`. No automatic quarantine. Avoid summing duplicate signatures or correlated rules as independent evidence. |
| 4 | No detection, but an enabled required stage is `partial`, `unavailable`, `error`, `timeout`, `cancelled`, or an object is unreadable/changed; an encrypted archive member is opaque; an internal parser or clamd limit was exceeded. | `unknown` | `false` | No quarantine; retry where appropriate and report the exact stage/coverage; `INCOMPLETE_COVERAGE`, `ENGINE_UNAVAILABLE`, `ENGINE_TIMEOUT`, `CHANGED`, etc. |
| 5 | No detection; every **applicable enabled** stage completed on the same file generation under its declared coverage, and no required subobject is opaque or omitted. | `clean` | `true` | No action; `COMPLETE_NO_DETECTION`. This remains “no threat found by these configured engines,” never a safety guarantee. |
| 6 | A stage was **disabled by policy** or intentionally inapplicable, with all applicable enabled stages complete. | `clean` only for the declared reduced policy; otherwise `unknown` if the product requires that stage | `false` for the full Gate v2 policy | Report `SKIPPED_BY_POLICY`; do not imply a full-gate clean. |

The conclusive ClamAV rule must implement the locked **weak-first** precedence: `PUA.*`, `Heuristics.*`, and an explicit reviewed weak-name denylist including the observed `Win.Trojan.Suspect-34` remain suspicious; `PUA.Win.Exploit.*` remains weak despite its later family token. `Generic`, `Gen`, and `Agent` are **not** weak merely by token. Unknown ClamAV names follow the owner’s locked quarantine default; `Packed`/`Obfuscated` receive no special rule until measured. `docs/handoff/PROJECT_CONTEXT.md:127-138`, `docs/handoff/PROJECT_CONTEXT.md:249-253`. A raw clamd name does not disclose whether it was a hash, body, logical, bytecode, or container-metadata signature; the policy therefore needs explicit provenance and a reviewed exception mechanism rather than an inferred “confidence” from spelling. [ClamAV signature formats](https://docs.clamav.net/manual/Signatures.html).

**Action guardrails.** Keep `should_auto_quarantine(verdict, policy) -> Decision` separate from classification and record a reason code. The default `legacy-v0` mode preserves the current action behavior until `evidence-v1` is explicitly enabled, as locked in `docs/handoff/PROJECT_CONTEXT.md:131-138`. Before any action, verify the pathname still resolves to the measured file generation; otherwise return `CHANGED_BEFORE_ACTION` and request a rescan. Restore should create only the locked **path+hash** exception, while persistent Trust remains a separate explicit action (`docs/handoff/PROJECT_CONTEXT.md:139-142`). The CLI precedence remains **malicious `2` > operational/incomplete failure `3` > suspicious `1` > clean `0`**, with deterministic policy-bounded partial coverage handled as specified in `docs/handoff/PROJECT_CONTEXT.md:245-248`.

**What would settle the remaining product uncertainties.** A vendor-published per-version scan log schema and policy document, plus a controlled benign-file test under documented offline, timeout, encrypted, oversized, stale-definition and crash conditions, would establish each product’s actual degraded verdict and action. Public marketing descriptions and detection names do not establish those outcomes. No such test was run in this round.
