# R8b — ClamAV 1.5.4 file types and parsers

**Scope.** I read this checkout and the specified Sentinel handoff files. `docs/research/R8a-clamav-engine.md` is absent. The findings below describe source-defined behavior, not a claim that every parser was exercised on files. Where a format’s behavior depends on the loaded signature database, build options, or a particular variant, I mark that boundary.

## 1. File-type recognition

| Step | Source-backed behavior | Consequence |
|---|---|---|
| Load magic definitions | `cli_loadftm()` loads built-in `ftypes_int[]` and optional `.ftm` records. A record contains magic mode, offset, pattern, name, required type, detected type, and optional minimum/maximum functionality level. Mode `0` inserts a fixed-byte file signature; mode `4` a partition signature; mode `1` an Aho–Corasick content pattern. Definitions outside the engine’s functionality level are skipped. `libclamav/readdb.c:2464-2581`, `libclamav/readdb.c:6007-6008` | Coverage depends on engine functionality level and loaded databases. |
| Initial type | `cli_magic_scan()` calls `cli_determine_fmap_type()` when passed `CL_TYPE_ANY` or `CL_TYPE_PART_ANY`. It does so from the mapped **bytes**. `libclamav/scanners.c:4774-4794` | A filename extension does not choose the parser in this path. The name remains available to metadata/signature matching; it is not a substitute for magic. |
| Fixed-offset magic precedence | `cli_compare_ftm_file()` walks the loaded linked list and returns the **first matching** fixed-byte type. `cli_loadftm()` prepends those records, so load order can matter. If none matches, it calls `cli_texttype()`. `libclamav/filetypes.c:261-280`, `libclamav/readdb.c:2570-2578` | There is no universal “longest magic wins” guarantee in this fixed-byte pass. |
| Secondary recognition | `cli_determine_fmap_type()` recognizes old/POSIX TAR after a binary fallback, refines ZIP to OOXML from member names, validates MBR versus GPT, and applies content signatures to text/binary classifications, including UTF-16/BOM conversion for HTML detection. `libclamav/filetypes.c:330-451`, `libclamav/filetypes.c:459-531` | “Magic versus extension” is incomplete shorthand: content patterns and internal container names can refine the initial type. |
| Unknown bytes | The fallback is a text encoding class or `CL_TYPE_BINARY_DATA`, not an “unscanned” type. `libclamav/filetypes.c:261-280`, `libclamav/filetypes.h:44-56` | Raw signatures can still match; a format-specific extractor may never run. |
| Recognized type without parser | The magic list recognizes Windows LNK and Python `.pyc`. `CL_TYPE_PYTHON_COMPILED` is explicitly sent to `cli_scan_fmap(..., CL_TYPE_OTHER, ...)`; there is no `CL_TYPE_LNK` case in either parser switch, so it receives the common raw scan but no shortcut-target/argument extraction. `libclamav/filetypes_int.h:189`, `libclamav/filetypes_int.h:207-208`, `libclamav/scanners.c:4938-5377`, `libclamav/scanners.c:5427-5486` | **Type recognition does not prove semantic inspection.** |
| Small or over-limit layer | Files of at most five bytes return success before pattern matching. A layer that fails `cli_updatelimits()` also returns success after recording a limit event internally. `libclamav/scanners.c:4745-4763` | An `OK` response alone does not prove that bytes or children were inspected. |

**Embedded types.** `scanraw()` combines malware matching with file-type signatures when type recognition is enabled. It deliberately disables embedded recognition for an already embedded layer and for GZIP, ZIP/OOXML, TAR, TNEF and some other types that have their own extraction path. It walks distinct nonzero offsets and may reclassify text as MHTML, XDP, or XML documents; otherwise recognized embedded content is scanned as a nested fmap with `LAYER_ATTRIBUTES_EMBEDDED`. `libclamav/scanners.c:3622-3683`, `libclamav/scanners.c:3685-3885` The explicit nested cases include RAR, EGG, ZIP, CAB, ARJ, 7z, NSIS, AutoIt, InstallShield MSI, PDF, and PE. ZIP/CAB/ARJ receive header checks; several other cases contain a source `TODO` for such validation. An embedded ZIP layer extracts only one entry. Embedded PE parsing has a `MaxEmbeddedPE` bound; ZIPs above `MaxZipTypeRcg` lose embedded-PE recognition. `libclamav/scanners.c:3888-4100`, `libclamav/scanners.c:5050-5060`, `libclamav/scanners.c:5389-5399`

## 2. Parser inventory

**Return-code rule for this table.** `cli_magic_scan()` runs raw matching and its parser switches, then calls `result_should_goto_done()`. `CL_VIRUS` and listed resource/I/O errors remain terminal. `CL_ETIMEOUT` halts that layer but is translated to `CL_SUCCESS`; `CL_EMAXREC`, `CL_EMAXSIZE`, `CL_EMAXFILES`, `CL_EFORMAT`, `CL_EPARSE`, `CL_EREAD`, and `CL_EUNPACK` are translated to `CL_SUCCESS` while scanning may continue. This is a *caller-visible normalization*, not proof that a parser succeeded. `libclamav/scanners.c:4415-4507`, `libclamav/scanners.c:5488-5498` “**Common result**” below means that rule applies; a signature alert, enabled heuristic, or terminal error can still change the final response. Global time, expanded-size, per-file-size, file-count, and recursion checks are implemented at `libclamav/others.c:1198-1318`, `libclamav/others.c:1782-1797`.

## Implications for Gate v2

1. **Track inspection separately from detection.** A ClamAV `FOUND` supplies evidence that a signature or heuristic matched. It does not prove the rest of the file or its children were inspected. `OK` is even narrower: it can follow a skipped encrypted member, unsupported ZIP/7z method, malformed parser result, exceeded limit, five-byte file, or unsupported ISO layout. `libclamav/scanners.c:4415-4507`, `libclamav/scanners.c:4745-4763`, `libclamav/7z_iface.c:207-223`, `libclamav/iso9660.c:344-350`

2. **Parse or explicitly mark opaque high-value forms.** Gate v2 should independently inventory LNK command fields; script/HTA language indicators; MSIX/AppX package relationships and signatures; VHD/VHDX; .NET single-file, ASAR and Python-packed payload inventories; and installer child files. For every archive/document it should record encrypted, unsupported-method, malformed, limit-hit and extracted-child counts. These are coverage requirements inferred from the missing or partial dispatch paths above. `libclamav/scanners.c:4938-5486`, `libclamav/filetypes.h:42-135`

3. **Use ClamAV alerts according to what they prove.** `Heuristics.Limits.Exceeded.*` and `Heuristics.Encrypted.*` mean **partial or unknown inspection**. `ContainsMacros`, broken media/executable, partition intersection, PDF name escaping and ZIP overlap are **structure/capability signals**. Exploit- and family-specific heuristics are **detection evidence**, subject to corroboration and false-positive policy. ClamAV itself categorizes `Heuristics.*` as potentially unwanted evidence unless heuristic precedence is requested. `libclamav/others.c:1720-1743`

4. **Do not treat any ordinary ClamAV text response as a certificate of complete inspection.** The source exposes no such response; the dispatcher deliberately normalizes several parser failures and limits to success. To settle completeness for a specific format/variant, Gate v2 needs independent format validation and child accounting, or a harmless fixture test that compares expected children with actual nested scans. `libclamav/scanners.c:4415-4507`, `libclamav/scanners.c:5027-5048`
