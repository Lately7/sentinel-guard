# RED25 — approved actions and their targets

Tests: `tests/codex/test_red25_actions.py`. Each uses `tmp_path` and the temporary `SENTINEL_HOME` fixture. I read the tests against the implementation and did **not** run pytest, as required by this round.

## Medium — restore can choose and trust a path the helper did not see

**Test:** `test_red25_restore_refuses_a_destination_changed_after_display`. **Attacker model:** an ordinary-user process can create a file at the original quarantine name while the elevated helper displays the restore plan. **Steps:** request a restore while the original name is free; the service describes only that original path. Create a harmless new occupant there, then approve. The second description is identical. `_unique_target` chooses `sample (restored).bin`; `_restore` adds a scan exception for that new path. **Effect:** the approved action writes and exempts a different path from the one shown to the administrator. **Lines:** `agent/sentinel/service/backend.py:600-608,637-645`; `agent/sentinel/service/core.py:322-331`; `agent/sentinel/quarantine.py:281-303,312-335`. **Fix:** bind the approved plan to the exact restore destination, or refuse the restore when the original destination becomes occupied and require a newly described plan for the alternate name. **Evidence:** proven by the in-process test logic; test unrun.

## Medium — restore confirmation omits Run values it will re-enable

**Test:** `test_red25_restore_plan_describes_autostart_undo`. **Attacker model:** an ordinary-user requester asks to restore an item created by an earlier approved repair. **Steps:** the repair journal contains a Run value removed with the quarantined file. The helper receives a restore summary describing the file path, digest prefix, and scan exception, with no Run value name. Approval then calls `repair.undo`, which writes the Run value. **Effect:** the helper can approve persistence restoration without seeing that action or its registry target in the current prompt. **Lines:** `agent/sentinel/service/backend.py:600-608,637-645`; `agent/sentinel/service/repair.py:317-333`; `agent/sentinel/db.py:651-659`. **Fix:** include the exact pending Run entries and their hives in the restore plan, refuse an overlong summary, and reject if those entries change before execution. **Evidence:** the omitted summary is proven by the in-process test logic; the execution effect follows directly from `repair.undo`; test unrun.

## Medium — repair undo overwrites a changed Run value

**Test:** `test_red25_restore_undo_preserves_a_changed_run_value`. **Attacker model:** an ordinary-user process changes its HKCU Run value after a repair removed the old one while the administrator views a restore plan. The same mechanism can affect HKLM when another authorized process changes it. **Steps:** create a quarantine item and an undo row for an old command; after the helper receives the plan, populate the Run name with a different command. `repair.undo` calls `SetValueEx` without checking the current value. **Effect:** restore silently replaces the newer command with the old autostart command, potentially re-enabling a quarantined program and undoing a later administrative choice. **Lines:** `agent/sentinel/service/backend.py:637-645`; `agent/sentinel/service/repair.py:317-333`. **Fix:** restore a Run value only if the name is absent; if it exists with other data, leave it intact and report the conflict. **Evidence:** proven by the in-process fake-registry test logic; test unrun.
