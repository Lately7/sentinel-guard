# R13 — Elevated architecture, real-time protection, downloads, and remediation

**Status:** read-only research. No files were modified, and no tests or elevated commands were run. **Proposal** marks a design recommendation; cited repository lines describe the current implementation or an earlier decision.

## 1. Elevated architecture

The owner’s new admin decision supersedes the earlier “no elevation” smart-scan scope in `PROJECT_CONTEXT.md:199-206` and the no-admin conclusions in `R12c-osquery.md:57-60` and `R12d-wazuh.md:114`. It does **not** change Gate v2’s evidence and action rules. The current program combines the tray, scanner, watcher, feed work, and database in one process (`agent/sentinel/tray.py:16-25,51-65,79-101`); installation registers a per-user native host and HKCU logon startup (`agent/sentinel/install.py:53-80`). That combined process should not simply be elevated.

| Option | Before logon and UI | Native host and tray connection | Assessment |
|---|---|---|---|
| **Windows service** | Automatic service can start before a user logs on. Services run in session 0; use a separate, unelevated tray in each interactive session. [Microsoft service isolation](https://learn.microsoft.com/en-us/windows/win32/services/service-changes-for-windows-vista). | Both clients connect to a local named pipe with a deliberate DACL and caller checks. | **Proposal: choose this.** It supports continuous machine coverage and a small privileged boundary. |
| **Highest-privilege task at logon** | A logon-triggered interactive task starts only after that user logs on; each user/session needs its own UI arrangement. A noninteractive task can start separately but still needs IPC. [Task logon types](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/ne-taskschd-task_logon_type), [task security contexts](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks). | Same pipe and validation requirements as a service. | Useful for a prototype, but leaves a pre-logon coverage gap and tends to elevate the full Python application. |
| **UAC-elevated tray** | Starts when a user approves elevation; no pre-logon protection, and closing the tray stops it. | The browser native host remains unelevated and still needs IPC. | Poor fit for persistent protection. UI and parser bugs would run with admin rights. |

**Proposal — service account and privileges.** Start with a *thin LocalSystem service* that owns event collection, source enumeration, authorization, and narrowly defined actions. LocalSystem supplies practical access to volume journals and other users’ profiles, but its local rights are broad even if token privileges are trimmed. A LocalService or `NT SERVICE\SentinelGuard` account is preferable if an owner-machine capability test proves it can open every required volume and source; neither name alone grants admin-equivalent access. LocalService has minimal local privilege, while service SIDs can protect only this service’s objects. Configure `SERVICE_CONFIG_SERVICE_SID_INFO` and `SERVICE_CONFIG_REQUIRED_PRIVILEGES_INFO`; the latter removes privileges not listed, but does not remove access granted by the account’s SIDs and object DACLs. [LocalService](https://learn.microsoft.com/en-us/windows/win32/services/localservice-account), [service isolation and required privileges](https://learn.microsoft.com/en-us/windows/win32/services/service-changes-for-windows-vista), [virtual accounts](https://learn.microsoft.com/windows-server/identity/ad-ds/manage/understand-service-accounts).

For the baseline, measure the token and retain only privileges actually used. `SeChangeNotifyPrivilege` is routine; `SeImpersonatePrivilege` is needed only if the pipe server impersonates clients. Do not include `SeDebugPrivilege`, `SeSecurityPrivilege`, `SeBackupPrivilege`, or `SeRestorePrivilege` by default. Make Security-log/SACL attribution and optional protected-source reads separate, explicit capabilities that enable only the necessary privilege for that operation. Ordinary `PROCESS_QUERY_LIMITED_INFORMATION` image lookup needs no `PROCESS_ALL_ACCESS` (`R12c-osquery.md:30,79`). Denials remain coverage entries, not a reason to silently add privileges.

**Proposal — IPC contract.** Use `\\.\pipe\SentinelGuard\v1` with `PIPE_REJECT_REMOTE_CLIENTS`, `FILE_FLAG_FIRST_PIPE_INSTANCE`, an explicit DACL granting the service SID full control and approved interactive user/logon SIDs only the needed client rights. Avoid broad `Everyone`/`Authenticated Users` write access and generic write rights that also grant pipe-instance creation. On every connection, verify the client’s token SID, logon/session identity, and integrity level; `GetNamedPipeClientProcessId` is diagnostic context, not authorization. For requests concerning a user’s files, impersonate the pipe client to check that user’s access, check impersonation success, and always `RevertToSelf`. Validate a versioned command allowlist, field types, length, path scope, rate limits, and response size. A browser-supplied path or URL never authorizes privileged mutation. [Named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [local-only pipes](https://learn.microsoft.com/windows/win32/ipc/named-pipes), [impersonation failure warning](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient).

**Proposal — Python installation boundary.** Install the service interpreter, application modules, `site-packages`, native dependencies, and update helper in an admin-writable location with no write access for ordinary users. The service must not load `.py`, `.pyc`, `.pth`, packages, rules, or DLLs from `%LOCALAPPDATA%`, a source checkout, the working directory, or a user-writable update cache. Launch Python with an absolute interpreter path and isolated configuration (`-I`, with compatibility tested), a fixed working directory, sanitized environment, and absolute paths for child programs and DLLs. `-I` excludes Python environment variables and user site-packages; it does **not** make a writable application directory safe. Windows DLL loading can consult the application directory, current directory, and `%PATH%`, so protect those paths and use secure DLL loading. Verify signed update packages, stage them in a protected directory, then switch versions atomically with rollback. Keep user settings and browser-native-host manifests separate from service code. The current `SENTINEL_HOME` override and per-user writable data directory (`agent/sentinel/config.py:20-44`) are unsuitable as a service code or trusted policy root. [Python isolated mode](https://docs.python.org/3.12/using/cmdline.html#cmdoption-I), [Python import path](https://docs.python.org/3.12/library/sys_path_init.html), [Windows DLL search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order).

## 2. Parsing untrusted files

The present scanner parses ZIP and PE data in-process and reopens some large files (`agent/sentinel/engine/scanner.py:69-123,178-219`). **Proposal:** the privileged service opens and identifies a file, then passes a read-only duplicate handle or a bounded snapshot to a separate low-privilege scan worker. The worker runs archive, PE, document, LNK, script, YARA-X, and ClamAV-client adapters. It returns versioned evidence plus byte/object coverage; the service verifies the worker identity, schema, file generation, deadline, and result limits before policy or action. Never send raw file bytes back through the tray or native-host pipe.

| Control | Benefit | Limit and Python cost |
|---|---|---|
| `CreateRestrictedToken` with disabled administrative SIDs and privileges | Restricts object access and privileged operations. | Requires an explicit launcher, token/ACL tests, and access grants for Python runtime files. [Microsoft restricted tokens](https://learn.microsoft.com/en-us/windows/win32/secauthz/restricted-tokens). |
| Low integrity | Prevents writes to ordinary medium-integrity objects even when their DACL would allow them. | Does not itself stop reading accessible files or using an allowed pipe. [Mandatory integrity control](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control). |
| AppContainer/LPAC | Stronger filesystem, registry, and network isolation through capabilities. | Python’s interpreter, extension modules, DLLs, temporary storage, and ClamAV socket need explicit packaging and ACL/capability work; adopt after the simpler worker is proven. [Launching an AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer). |
| Job Object | Caps memory/process count/CPU and kills the worker tree on timeout or broker exit. | Resource limits do not authorize access or guarantee a blocked I/O finishes; retain per-stage wall-clock deadlines. [Job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information). |

**Proposal:** initially use a restricted, low-integrity worker in a Job Object, with no network, no child processes except a separately brokered ClamAV operation, read-only handles, and a private scratch directory. Test Python and YARA-X compatibility before considering AppContainer. The privileged side alone performs: opening a source unavailable to the user; protected quarantine-store writes; enumerating other users’ profiles and machine persistence; restricted process termination; and approved registry, service, task, WMI, and file repair. Parsing must never occur in the privileged side merely because it opened the file.

## 3. Real-time protection without a driver

Admin rights permit better *observation and reconciliation*. They do not provide a reliable pre-execution decision point. Microsoft describes a filesystem minifilter as the component that can intercept and prevent file I/O; this project has no signed minifilter, ELAM, or PPL. A user-mode scan triggered by a write, rename, process-start event, or first observed open can finish after execution begins. It also cannot protect itself from a local admin or protected-process tampering. [Microsoft minifilter overview](https://learn.microsoft.com/en-us/Windows-hardware/drivers/ifs/about-file-system-filter-drivers).

- **USN journal.** **Proposal:** use `FSCTL_QUERY_USN_JOURNAL` and `FSCTL_READ_USN_JOURNAL` per eligible NTFS volume as a durable change cursor and overflow recovery source. Persist `(volume ID, journal ID, next USN, checkpoint time)`. Reconcile when watchdog overflows, restarts, or falls behind. A journal can wrap, be deleted/recreated, or become inaccessible; `ERROR_JOURNAL_ENTRY_DELETED` or changed journal ID means a full bounded reconciliation is needed. Thus “gap-free” applies only while the recorded cursor remains valid, and it is change tracking, not complete scan coverage. `REVIEWS.md:134-135` records that today’s 10,000-path cap reports overflow but does not reconcile. [USN journal](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/fsutil-usn), [read cursor errors](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-read_usn_journal_data_v0).
- **Process starts.** **Proposal:** prototype `Microsoft-Windows-Kernel-Process` ETW start events (or `Win32_ProcessStartTrace` as a simpler fallback), query the image with limited process rights, and submit an urgent scan if its file generation is unknown. Image-load ETW is useful as contextual inventory; kernel-file ETW is high volume and should be a measured, optional experiment. ETW reports lost events; on loss, mark coverage degraded and take a process snapshot. It still cannot block process creation. [System ETW providers](https://learn.microsoft.com/en-us/windows/win32/etw/system-providers), [WMI process start](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/krnlprov/win32-processstarttrace), [ETW lost-event reporting](https://learn.microsoft.com/en-us/windows/win32/etw/consuming-events).
- **Writer attribution.** Security event 4663 can identify a process and file when audit policy and the object’s SACL request the relevant access. SACL operations need `SeSecurityPrivilege`. **Proposal:** make narrow, owner-approved attribution on selected folders optional; never enable broad file auditing as the default or treat missing 4663 as proof of no write. `R12d-wazuh.md:103-114` describes the cost and prior no-admin exclusion. [Event 4663](https://learn.microsoft.com/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4663), [SACL privilege](https://learn.microsoft.com/en-us/windows/desktop/SecAuthZ/sacl-access-right).

**Proposal — queue design.** Retain watchdog for low-latency hints in selected high-risk roots; add USN cursors on fixed NTFS volumes for recovery. Full fixed-volume real-time scanning of *every changed file* is too costly until measured; deep scan can cover all fixed volumes. Use two file workers initially, four maximum, the R11 192–256 MiB weighted in-flight budget, a single Defender slot, and per-stage deadlines (`PROJECT_CONTEXT.md:207-220`). A bounded `PriorityQueue` should carry `{source, volume, file_id, observed_usn, path_hint, reason, first_seen, due, generation}`. Priority 0: newly executed images and completed executable/script downloads; 1: executable/script/archive writes and persistence targets; 2: other high-risk-root changes; 3: reconciliation. Deduplicate by file identity plus generation, coalesce repeat writes, and reserve capacity for priority 0 and durable terminal events. Per-root counters must distinguish received, coalesced, dropped, retries, USN gaps, discovered entries, scanned generations, and actions. On saturation, mark the root `partial`, schedule reconciliation, and show the debt until resolved. Preserve R11’s same-generation evidence, no-false-clean, bounded-work, and stop-barrier invariants (`R11:46-64`); the existing watcher already has retries and a stop/action lock (`agent/sentinel/watcher.py:26-43,55-75,180-211`) but lacks this volume reconciliation.

## 4. Downloaded files

The current extension sends `{path, url}` after Chromium reports completion (`extension/src/background.js:289-333`). The native host scans that path and may add a critical finding from URL reputation (`agent/sentinel/nativehost.py:143-159`). MotW is read from `:Zone.Identifier` with an 8 KiB cap (`agent/sentinel/engine/motw.py:24-46`).

**Facts.** `Zone.Identifier` can carry `ZoneId`; `HostUrl` and `ReferrerUrl` are useful origin context when present. Windows uses MotW for attachment security decisions. The stream is writable metadata and may be absent after copying, extraction, filesystem changes, or application-specific download handling. Archive extraction propagation varies by extractor and Windows version; Sentinel must test the actual extractor and scan archive members regardless of whether child files receive MotW. [Microsoft Zone.Identifier format](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/6e3f7352-d11c-4d76-8c39-2516a9df36e8), [Attachment Manager](https://support.microsoft.com/en-us/windows/security/information-about-the-attachment-manager-in-microsoft-windows).

**Proposal — completion and rescan.**

1. Detect final rename/close or stable size on watched Downloads and other configured roots, including files from Helium, Chrome, Edge, Firefox, email clients, and download managers. Browser API events provide timely URL context but cannot be the only discovery source. Keep provisional `.crdownload`, `.part`, and similar files as incomplete; current suffix and maximum-age handling is in `watcher.py:21-40,96-117`.
2. Scan the final *file generation*: outer bytes, executable/script structure, bounded archive inventory and members, YARA-X, ClamAV, Defender, MotW, and signer context under the Gate v2 contract. Prioritize executable/script/archive content. `partial`, timeout, encrypted child, or unavailable engine is visible coverage debt.
3. Rescan at first observed execution if the content or gate generation has changed, or its last result was incomplete. Requeue retained downloads when signature/policy generation changes; use a bounded index keyed by `(volume/file ID, SHA-256, gate generation)` and a time/space budget. A cached result cannot become stronger merely because signatures updated (`R11:119-130`).
4. Keep URL and MotW as distinct, untrusted provenance fields. A browser’s claim that a URL produced a path is not sufficient to let a privileged service quarantine an arbitrary file. Bind a download report to the requesting user, an opened file identity/generation, and a completed scan. A blocklisted URL can prompt a warning or browser cancellation; automatic file action still needs the accepted conclusive evidence required by R11 (`R11:362-405`). This revises the current critical URL-origin promotion in `nativehost.py:152-157`.

**Proposal — `scan_download` IPC:** the unelevated native host becomes a thin request client. It sends a bounded `download_complete` hint containing browser download ID, URL, and path; the service checks the pipe caller, verifies access while impersonating that caller, admits only a regular local file, opens it itself, records identity, and returns a job ID. The service reports typed scan/coverage/action results asynchronously. An `ok` IPC response means *accepted for scanning*, not *scanned*. Preserve the extension’s failed hand-off retry behavior (`background.js:309-325`; `REVIEWS.md:141`) and display unknown/partial outcomes explicitly.

## 5. Smart scan and deep scan

**Proposal — smart scan:** preserve the locked one-button scope in `PROJECT_CONTEXT.md:191-206`, then extend machine visibility deliberately: watched roots for all local user profiles, every user and All Users Startup, HKU user hives plus HKLM Run/RunOnce in both views, all Task Scheduler folders recursively through COM, machine services’ `ImagePath`, running process images, and downloaded-file debt. A service’s HKCU is the service account’s hive, so per-user entries must be addressed by user SID under HKU or a properly loaded hive. Task enumeration must use `ITaskService → ITaskFolder::GetFolders/GetTasks`, with each denied folder recorded; `R12c-osquery.md:10-16,77-79` documents why silent omissions and raw `System32\Tasks` traversal are insufficient. [Task Scheduler COM](https://learn.microsoft.com/en-us/windows/win32/api/_taskschd/).

**Proposal — confirmed deep scan:** add all fixed local volumes; installed service and driver inventories; every Task Scheduler folder and action; WMI `__EventFilter`, consumer, and binding entries; IFEO/debugger, AppInit, Winlogon, COM registration/hijack locations; browser extension manifests for each discovered profile; `hosts`; running images and accessible modules. Autoruns publicly documents these classes as autostart locations. WMI permanent consumers are distinct persistent registrations. Optional process-memory YARA-X scanning requires a separate feature, explicit consent, minimal `PROCESS_VM_READ` access, and `access_denied` reporting for protected processes; even admin rights do not grant unrestricted access to protected processes. Do not call a disk-only scan “memory clean.” [Autoruns categories](https://learn.microsoft.com/en-us/sysinternals/downloads/autoruns/), [WMI permanent consumers](https://learn.microsoft.com/en-us/windows/win32/wmisdk/monitoring-events), [process access](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights).

**Proposal — budgets and report:** keep the existing confirmed whole-machine/deep-scan expectation and provisional two-hour budget (`docs/ROADMAP.md:84-91`). Use resumable per-source cursors, two workers/four maximum, 256 MiB weighted memory, per-file 120-second deep deadline, bounded archive depth/member/expanded-byte limits, and measured disk-I/O throttling. Do not silently raise limits because the service is admin. A source-entry ledger should record `{source_type, source_id, user_sid, discovered, resolved, queued, scanned, denied, vanished, unsupported, excluded_by_policy, timed_out}`; file results remain deduplicated by handle identity. Report both source-entry coverage and file/engine coverage. The current `scanjob.walk` keeps at most 1,000 error strings and the progress structure counts scanned/unreadable files, but it has no denominator for denied source entries (`agent/sentinel/scanjob.py:48-71,80-97,131-173`). R11 already requires source-entry coverage (`R11:56-64,87-88,429`).

## 6. “Scan and repair”

**Proposal:** “repair” is a staged, reviewable plan derived from specific evidence, not a synonym for deleting every suspicious item. Public products separate detection and action: Defender describes clean, quarantine, remove, block, and restore choices, and its action history supports undo for several action types; Malwarebytes exposes automatic quarantine as a setting. Autoruns presents autostart entries for manual inspection. These are product descriptions, not an assertion that Sentinel can reproduce their internal guarantees. [Defender remediation](https://learn.microsoft.com/en-us/defender-endpoint/configure-remediation-microsoft-defender-antivirus), [Defender undo actions](https://learn.microsoft.com/en-us/defender-endpoint/manage-auto-investigation), [Malwarebytes scan settings](https://help.malwarebytes.com/hc/en-us/articles/41813847845275-Malwarebytes-for-Windows-scan-settings), [Autoruns](https://learn.microsoft.com/en-us/sysinternals/downloads/autoruns/).

**Proposal — action sequence:** present evidence, source, affected file generation, proposed steps, and rollback limits. Revalidate all identities immediately before acting. For an accepted conclusive file detection, quarantine the file; if a related process is active, ask for confirmation before terminating its verified process tree, then quarantine and disable only the identified persistence entry. Back up exact prior registry value/type, task XML/security metadata, service configuration, WMI objects/bindings, or `hosts` bytes/ACL before modification. Restore `hosts` from a known-good owner-approved baseline or from the captured backup after removing only the confirmed malicious modification; never replace it with a generic template. For a locked file, `MoveFileExW(..., MOVEFILE_DELAY_UNTIL_REBOOT)` may schedule a deletion/rename; that API only confirms registry scheduling, so report `pending_reboot` and verify the actual result after restart. [MoveFileEx](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-movefileexa).

A durable `RepairPlan` should have `plan_id`, policy/evidence versions, caller SID, confirmation level, and ordered `RepairStep` records with `object_identity`, precondition hash/config, before-image reference, operation, state (`prepared`, `applied`, `verified`, `rollback_pending`, `rolled_back`, `failed`, `pending_reboot`), timestamp, and error. Flush the prepared step before each external action; record applied and verified separately. On crash, reconcile against the object’s current identity before retry or rollback. Registry/task/service/file operations are not one atomic transaction. Process termination is irreversible; label it as such rather than promising rollback. Never overwrite a changed object during rollback.

**Proposal — confirmation levels:**

- **Automatic:** only ordinary-file quarantine when Gate v2 has accepted conclusive evidence, current identity/hash, current protection generation, and no protected-file exclusion (`R11:394-405`). No automatic persistence deletion or process termination initially.
- **One explicit confirmation:** terminate a verified nonprotected process tree, disable/remove its precisely linked user-level Run value or task, or restore a clearly attributable `hosts` change.
- **Step-by-step expert confirmation:** machine services, drivers, WMI consumers, IFEO/AppInit/Winlogon/COM keys, reboot operations, or repairs affecting another user. Record a rollback plan before enabling each operation.

Never mutate Windows-protected files, trusted signed Microsoft components, Defender settings, or security-product configuration. A signature is contextual evidence, not blanket “clean”; a trusted Microsoft component nevertheless belongs on the *no Sentinel repair* side of this safety boundary. On ambiguous ownership, changed identity, incomplete scan, or inability to make a reliable before-image, report and refer to the owner/manual tool instead of acting. This is consistent with the repository’s existing ban on changing Defender settings (`PROJECT_CONTEXT.md:259-273`).

## 7. Gate v2 impact and ordered implementation

**Preserve:** all R11 invariants 1–15 (`R11:46-64`): no false clean, one file generation, accepted evidence, separate verdict/action, weak-signal restraint, bounded coverage/work, cancellation, identity-bound action, stop barrier, cache limits, scoped exceptions, event privacy, and honest scope. Milestones 1–2 already exist (`R11:435-448`; `REVIEWS.md:160-183`); do not redesign or reopen them. The earlier no-elevation and no-process-memory scope in `PROJECT_CONTEXT.md:199-206` changes only as explicitly labeled new scan modes. The owner’s one Scan button and live pipeline remain (`PROJECT_CONTEXT.md:191-227`).

**Proposal — add invariants:**

16. **Privilege separation:** no untrusted-file parser or browser/UI message handler runs with the service’s action token.
17. **Authenticated, scoped IPC:** every privileged request is bound to an identified local caller and an allowlisted operation; caller-provided paths, URLs, and serialized evidence never authorize an action alone.
18. **Repair journal and recovery:** every external mutation has a durable before-image, precondition, result, verification, and rollback/irreversibility status.
19. **Observation is not prevention:** USN, ETW, WMI, MotW, and watchdog events are hints with loss counters; none certifies pre-execution blocking.
20. **Machine-source coverage:** denied hives, folders, tasks, services, volumes, or process images remain explicit report entries.

**Proposal — implementation order and acceptance:**

Keep privileged operations disabled. | Malformed/oversized frames, wrong SID/session, path outside caller access, replay/stale file generation, rate limit, reconnect, and extension pending-download tests. |
